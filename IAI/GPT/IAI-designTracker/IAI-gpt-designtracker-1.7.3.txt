1. ESSENCE
================================================================================

WHAT IT IS
  An sklearn Pipeline: a single object that chains preprocessing
  (scaling) and the classifier into one estimator-like construct.

  A Pipeline has .fit(X, y), .predict(X), .score(X, y) — externally it
  looks like any other sklearn estimator. Internally it chains steps:
      fit()     -> fit_transform() on each intermediate step,
                   fit() on the final step (classifier)
      predict() -> transform() on each intermediate step,
                   predict() on the final step

HOW IT WORKS
  Steps are (name, object) tuples. For this project, two steps:
      ("scaler", StandardScaler())
      ("clf",    <classifier>)

  Instantiation is cheap. Fitting is what runs the chain.

WHY IT EXISTS AS A STEP SEPARATE FROM 1.7.2
  1.7.2 fitted a StandardScaler on the FULL training set (one-shot fit
  for inspection). That is correct for the report figures it produces,
  but NOT correct for cross-validation.

  Phase 2 runs CV. CV splits the training set into K folds. For each
  fold:
      - fit on K-1 folds
      - evaluate on the held-out fold

  If scaling is done BEFORE CV (as 1.7.2 does for inspection), then
  each fold's held-out portion was already scaled using statistics that
  include that fold. The fold's test data influenced its own scaling.
  This is DATA LEAKAGE. Evaluation is no longer honest.

  The Pipeline solves this. When a Pipeline sits INSIDE
  cross_val_score or GridSearchCV, sklearn RE-FITS THE ENTIRE PIPELINE
  — including the scaler — INSIDE EACH FOLD, using only that fold's
  training portion. The held-out portion is transformed using scaler
  parameters derived only from the training portion. No leakage.

THE MENTAL MODEL
  1.7.2's scaler = one-shot fit for inspection.
  1.7.3's Pipeline = production-grade scaler that refits per CV split.

THE KEY CONSEQUENCE
  1.7.3 does NOT write a CSV. It produces a Python function /
  object. Phase 2 instantiates and uses it directly. This is a
  code-level artefact, not a data-level one.

  Every earlier step in Phase 1 produced a file. 1.7.3 is the first
  step that produces only code. This is deliberate and correct.

--------------------------------------------------------------------------------
1.1 SCOPE OF THE PIPELINE
--------------------------------------------------------------------------------
The Pipeline contains exactly two steps:

    Step 1: scaling      (StandardScaler)
    Step 2: classifier   (SVM / k-NN / RF — supplied by Phase 2)

It does NOT contain cleaning (1.7.1). Reasoning:

  - 1.7.1's cleaning is conditional (clip / remove / keep) and its
    thresholds were derived from the full train set. Strict CV
    correctness would require cleaning to refit inside each fold too.
  - The practical impact on this dataset is small: clipping alters
    only the tails of 5 continuous features, and the thresholds were
    derived from train only (per 1.7.1 R1 correction).
  - Wrapping cleaning in a custom sklearn transformer adds complexity
    and test burden for marginal benefit.

  Decision: cleaning stays OUTSIDE the Pipeline. Documented as an
  accepted simplification in Preliminary §3 and Full ML §6.

  If a future revision wants strict CV correctness for cleaning, add
  a FunctionTransformer wrapping the 1.7.1 clip logic as step 0.

--------------------------------------------------------------------------------
1.2 WHAT THE PIPELINE IS NOT
--------------------------------------------------------------------------------
  - NOT a data file. No CSV is written.
  - NOT a trained model. It is a factory: build_pipeline(classifier)
    returns a fresh, unfitted Pipeline on each call.
  - NOT a replacement for 1.7.2's diagnostic figures. Those remain
    valid for the report.
  - NOT a component of Phase 4. The CNN branch reads crops directly.

    2. 1.7.2 has chosen StandardScaler and produced inspection figures.
    3. 1.7.3 runs:
       - define build_pipeline(classifier) -> Pipeline

    4. Phase 2 (2.1.x):
       - calls build_pipeline(SVC())
       - calls build_pipeline(KNeighborsClassifier())
       - calls build_pipeline(RandomForestClassifier())
       - one Pipeline per classifier candidate.
    5. Phase 2 (2.2.x):
       - wraps each Pipeline in GridSearchCV or cross_val_score.
       - scaler refits inside each fold.
    6. Phase 2 (2.3.x):
       - evaluates best Pipeline on val, then test.
    7. Phase 3 (3.2.2):
       - retrains best Pipeline on full training set.
       - persists with joblib.dump().

BEFORE 1.7.3: preprocessing exists as separate scripts that each
              produce files (or in-memory matrices for 1.7.2).
AFTER 1.7.3:  preprocessing is encapsulated in one reusable object.
              Phase 2 no longer touches feature files directly — it
              instantiates the Pipeline and fits.

    # src/pipeline.py
    from sklearn.pipeline import Pipeline
    from sklearn.preprocessing import StandardScaler

    # ========================================================================
    # [PARAMETERS - FILL IN BEFORE RUN]
    # ========================================================================
    SCALER_CLASS           = [SCALER_CLASS]        # StandardScaler
    FEATURE_STEP_NAME      = "scaler"              # step name inside Pipeline
    CLASSIFIER_STEP_NAME   = "clf"                 # step name inside Pipeline

    # ========================================================================
    # FACTORY
    # ========================================================================
    def build_pipeline(classifier):
        """
        Return an sklearn Pipeline: scaler -> classifier.

        The scaler refits inside each CV fold, preventing leakage.
        Caller supplies the classifier (SVC, KNeighborsClassifier,
        RandomForestClassifier, etc.).

        Do NOT pass a fitted scaler. The Pipeline must own it.
        """
        return Pipeline([
            (FEATURE_STEP_NAME,    SCALER_CLASS()),
            (CLASSIFIER_STEP_NAME, classifier),
        ])

    # ========================================================================
    # OPTIONAL SMOKE TEST (run once before Phase 2 commits)

    if __name__ == "__main__":

        pipe = build_pipeline(DummyClassifier())
        print(pipe)
        # Expect: Pipeline(steps=[('scaler', StandardScaler()),
        #                         ('clf',    DummyClassifier())])

5. RECOMMENDATIONS FOR THIS PROJECT
================================================================================

RECOMMENDATION 1 - KEEP CLEANING OUTSIDE THE PIPELINE
    Pipeline = [StandardScaler, Classifier]. Cleaning is a once-only
    operation (1.7.1). Document this as an accepted simplification in
    Preliminary §3 and Full ML §6.

    Strict CV correctness for cleaning is a possible refinement. It is
    not worth the complexity for this dataset.

RECOMMENDATION 2 - ONE PIPELINE PER CLASSIFIER
    Phase 2 compares SVM, k-NN, RF. Each gets its own Pipeline, because
    the classifier is the last step of the chain. Do not share one
    Pipeline across classifiers.

RECOMMENDATION 3 - TUNE THROUGH THE PIPELINE, NOT AROUND IT
    In Phase 2's grid search, hyperparameters are addressed with a
    step-name prefix:
        param_grid = {
            "clf__C":     [0.1, 1, 10],
            "clf__gamma": ["scale", 0.01, 0.1],
        }
    The "clf__" prefix routes the parameter to the classifier inside
    the Pipeline. "scaler__*" would route to the scaler (StandardScaler
    has no tunable parameters for this project, so it will not appear
    in the grid).

    Do NOT pass the classifier separately to GridSearchCV. Always wrap
    it in the Pipeline.

RECOMMENDATION 4 - PERSIST THE FITTED FINAL PIPELINE IN PHASE 3
    After Phase 2 picks the best classifier and retrains the Pipeline
    on the full training set, serialize it:
        import joblib
        joblib.dump(fitted_pipeline, "models/best_pipeline.joblib")
    For inference in Phase 3:
        import joblib
        pipe = joblib.load("models/best_pipeline.joblib")
        y_pred = pipe.predict(X_new)
    The scaler parameters travel with the model, so inference uses
    exactly the same scaling as training. This is the practical payoff
    of using a Pipeline.

WHY THIS MATTERS FOR THE ASSESSMENT
    The IAI rubric explicitly rewards:
      Level 3: "Preprocessing pipeline discussed and implemented"
      Level 4: "at least one alternative preprocessing method"

    A real sklearn Pipeline, correctly refitting inside CV, cleanly
    satisfies Level 3. Level 4 can be reached with a one-line change
    (swap StandardScaler for MinMaxScaler) and a comparison run.

    The report can honestly claim "no data leakage across folds"
    because the Pipeline structure guarantees it. Without a Pipeline,
    a reviewer will ask how the scaler avoided leakage. The note and
    code answer that question.

WHAT TO AVOID
    - Do not add the classifier OUTSIDE the Pipeline and pass a
      pre-scaled dataset to cross_val_score. That reintroduces the
      1.7.2 leakage.
    - Do not feed 1.7.2's dataset_*_scaled.csv into the Pipeline.
      Double-scaling.
    - Do not include cleaning as a custom transformer unless you have
      time to implement and test it. Marginal benefit, real
      complexity cost.
    - Do not cache the fitted Pipeline across CV folds. Each fold
      must refit. sklearn does this automatically when the Pipeline
      is inside GridSearchCV / cross_val_score.

TIMEBOX
    10 minutes to write the factory function and smoke-test it. No
    reading of output is required. No report paragraph is dedicated
    to 1.7.3; it is covered by the §3 preprocessing narrative.

8. RESCALE / FALLBACK TRIGGERS
--------------------------------------------------------------------------------
    - If a Pipeline fails to fit inside GridSearchCV:
        -> check that the classifier is INSIDE the Pipeline, not
           alongside it. Check param grid keys use clf__ prefix.
    - If CV scores are suspiciously high (>99% on 15 classes):
        -> leakage. Confirm the Pipeline is inside cross_val_score /
           GridSearchCV, not wrapping it.
    - If Phase 3 inference predictions differ from Phase 2 test
        predictions on the same inputs:
        -> the scaler was re-fitted on different data, or the wrong
           scaler was loaded. Persist and reload the fitted Pipeline
           as a unit, not the scaler and classifier separately.

ADDITION 1 - PRECONDITIONS LINE IN build_pipeline DOCSTRING
--------------------------------------------------------------------------------
WHERE IN R0:
    Section 4 - build_pipeline() docstring lists the caller's
    responsibility ("Caller supplies the classifier") but does not

WHY IT MATTERS:
    The factory assumes X contains only numeric feature columns
    (the retained set from 1.6.3). If the caller accidentally passes
    the full dataframe — with filename, label, or role columns
    included — the scaler will raise a ValueError at fit time with a
    message that points at the scaler, not at the actual mistake.
    Common slip when copying X from a pandas dataframe without
    dropping non-feature columns.

FIX:
    Extend the docstring with an explicit PRECONDITIONS block.
    No code change required.

    Section 5  - "WHAT TO AVOID" gains one reinforcing bullet


--------------------------------------------------------------------------------
ADDITION 2 - DO NOT PASS A PRE-FITTED CLASSIFIER
--------------------------------------------------------------------------------
WHERE IN R0:
    Section 4 - docstring includes "Do NOT pass a fitted scaler."
    It does not similarly forbid a pre-fitted classifier.

WHY IT MATTERS:
    Symmetric failure to the pre-fitted-scaler case. If the caller
    passes a classifier that has already been fitted on the full
    training set, the Pipeline will contain a pre-committed final step.
    When GridSearchCV / cross_val_score refits the Pipeline per fold,
    sklearn will call .fit() on the classifier again — which typically
    reinitialises it — but a caller who passes a fitted estimator and
    then inspects parameters may misinterpret the state. More
    importantly, some sklearn versions do not refit an already-fitted
    estimator cleanly in certain CV configurations. The Pipeline must
    own both steps in an unfitted state.

FIX:
    Extend the docstring and the "WHAT TO AVOID" list with the
    symmetric rule. No code change required.

SECTION REFERENCES:
    Section 4  - docstring, extends existing "Do NOT" line
    Section 5  - "WHAT TO AVOID" gains the symmetric bullet
