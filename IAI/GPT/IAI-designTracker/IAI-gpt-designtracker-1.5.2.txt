--------------------------------------------------------------------------------
1. ESSENCE
--------------------------------------------------------------------------------
A mask is a binary image: 0 (ignore) or 255 (keep). It is the output of 1.5.1.

The numeral-region mask is a STENCIL of the white circle patch on the ball.
The numeral itself appears as a HOLE inside that stencil — the numeral is
not present in the mask, it is enclosed by it.

1.5.2 converts each mask into a fixed-length vector of NUMBERS describing its
structure. That vector is the input to classical ML.

WHY NOT USE RAW PIXELS:
  - A 60x60 mask is 3,600 binary values. Too many features for ~750 samples
    (curse of dimensionality).
  - Rotation moves every pixel. Pixel-level features are maximally fragile.
  - Not interpretable. Cannot justify "pixel (17,42) matters" in a report.

Shape features compress the mask into 23 numbers that capture the numeral
structure without carrying raw pixel positions.

4. FEATURE CATALOGUE (ALL METHODS)
--------------------------------------------------------------------------------

DEFAULT SET (used first):

(a) hole_count
    Number of connected holes inside the largest blob.
    Rotation-invariant. Expected to group numerals as:
      0 holes:  1, 2, 3, 5, 7, 11, 12, 13
      1 hole:   0, 4, 6, 9, 10, 14, 15
      2 holes:  8
    NOTE: this grouping is a hypothesis, not a verified result. Numerals
    like "15" may render differently across ball designs, and the "1" and
    "5" regions may or may not merge into a single hole. Validate the
    grouping during 1.6 EDA. Reported as a hypothesis in the report.
    Strongest single feature in the set. Survives mask noise well.

(b) connected_component_count
    Number of connected white components in the full mask.
    Mostly 1 for single-digit numerals, may be 2 for two-digit numerals
    (10-15) if the mask fragments. Rotation-invariant.

(c) blob_area_ratio
    Largest blob pixels / crop area (H*W).
    Captures how much of the crop is "white region".
    NOTE: solid balls (1-8) produce a small mask (just the patch);
    striped balls (9-15) leak white stripe pixels into the mask, inflating
    this ratio. This means blob_area_ratio partially encodes solid-vs-stripe
    — coincidentally useful for 6/9, but must be flagged as a known bias in
    the report, not treated as a discovery.

(f) hole_area_ratio
    Largest hole pixels / blob area.
    Distinguishes wide numerals (8, 0) from narrow (1).

(g) hole_aspect
    Largest hole bounding-box width / height.
    "1" is tall and thin (small ratio); "8" is roughly square (~1).
    For two-digit numerals, this becomes a proxy for whichever digit
    dominates the hole region.

(h) hole_centroid_dx, hole_centroid_dy
    Offset of the largest hole's centroid from the blob centroid, in blob
    units. "1" tends to sit off-centre; "8" is central. Two features.

(i) x/y projections, 8 bins each
    Horizontal and vertical mass distribution of the largest blob,
    binned to 8 groups per axis, normalised by blob area.
    Captures single-peak (single-digit) vs double-peak (10-15) structure.
    ROTATION-SENSITIVE: a rotated numeral shifts the profile. This is
    expected and documented as a Phase 2 limitation.

FALLBACK SET (used if defaults under-deliver):

(d) blob_circularity
    4*pi*area / perimeter^2. Near 1.0 for all classes (all blobs are
    circular patches). Included only if a specific failure suggests it.

(e) blob_aspect
    Blob bounding-box width / height. Near 1.0 for all classes.
    Included only if a specific failure suggests it.

(j) Hu moments on hole
    Seven rotation-invariant moments of the largest hole (the numeral).
    Can distinguish "1" vs "8". BUT makes "6" and "9" IDENTICAL — the exact
    pair we cannot afford to confuse. Included as auxiliary only.

DEFAULT COMBINATION TOTAL: 7 categories / 23 sub-features
  (a) hole_count                      1
  (b) connected_component_count       1
  (c) blob_area_ratio                 1
  (f) hole_area_ratio                 1
  (g) hole_aspect                     1
  (h) hole_centroid_dx, _dy           2
  (i) proj_x_0..7, proj_y_0..7       16
  -------------------------------------
  Total:                             23

5. DESIGN DECISIONS - ALL CONFIRMED
--------------------------------------------------------------------------------

(a) Hole detection method: connected components on the inverted blob,
    excluding components touching the image border (those are background).
    Rejected: cv2.findContours with RETR_CCOMP hierarchy — works but is
    fussier to filter by border contact.

(b) Morphology at 1.5.1: opening = 1, closing = 0.
    Closing is kept at 0 because closing would FILL the numerals 0, 6, 8, 9
    and destroy the hole-count feature. This decision is inherited from
    1.5.1 and is what makes 1.5.2 possible.

(c) Projection bins: 8 per axis. Fallbacks: 4 (coarser), 16 (finer),
    32 (very fine). 8 chosen to preserve single-vs-double-peak structure
    while keeping feature count low relative to sample size.

(d) Hu moments: OFF by default. Retained as optional auxiliary (j).

(e) Class scheme: FLAT 15-CLASS.
    Rejected: two-stage tens/units classification.
    Rationale (learner's): a 12-ball rolled halfway presents only "1" or
    "2" to the camera. A two-stage classifier would classify it as the
    visible single digit. Flat 15-class forces the model to learn the
    WHOLE numeral region as one class, which is correct even when the
    numeral is partially visible.

(f) Mask storage: mask_png\1\ ... 15\ (parallel tree to unsorted_png\).
    Path substitution 1:1: unsorted_png\C\X.png -> mask_png\C\X_mask.png.
    Rejected:
      - Mixed into crop folders: no filter protection; downstream loaders
        would silently pick up masks if *_mask.png was not filtered.
      - Flat dump without class subdirs: forces filename parsing to recover
        the class; breaks per-class iteration.

(g) Blob-area normalisation reference: crop area (mask H * mask W).
    Rejected: total mask white pixels (all components), largest blob only
    (ratio identically 1 — nonsense).

(h) Projection normalisation reference: blob area (largest component).
    Rejected: total mask white pixels, total projection sum (equivalent
    to total white pixels).

# ============================================================================
# HELPERS
# ============================================================================
def largest_blob(mask):
    """Return (blob_mask, blob_stat) for the largest connected component.
    blob_mask is uint8 {0,255}. blob_stat is the OpenCV stats row."""
    n, labels, stats, _ = cv2.connectedComponentsWithStats(mask, 8)
    if n <= 1:
        return None, None
    idx = 1 + int(np.argmax(stats[1:, cv2.CC_STAT_AREA]))
    blob = (labels == idx).astype(np.uint8) * 255
    return blob, stats[idx]


def find_holes(blob_mask, min_area_px):
    """Return list of stats rows for holes inside blob_mask.
    A hole is a connected component of the inverted blob that does not
    touch the image border (those are background)."""
    inv = cv2.bitwise_not(blob_mask)
    n, labels, stats, _ = cv2.connectedComponentsWithStats(inv, 8)
    h, w = blob_mask.shape
    holes = []
    for i in range(1, n):
        x, y, ww, hh, area = stats[i]
        if x == 0 or y == 0 or x + ww == w or y + hh == h:
            continue                       # touches border -> background
        if area < min_area_px:
            continue                       # too small -> noise
        holes.append(stats[i])
    return holes


def projections_binned(blob_mask, n_bins, blob_area):
    """Return (x_bins, y_bins), each length n_bins, normalised by blob_area."""
    col_sums = (blob_mask > 0).sum(axis=0).astype(float)
    row_sums = (blob_mask > 0).sum(axis=1).astype(float)
    x_chunks = np.array_split(col_sums, n_bins)
    y_chunks = np.array_split(row_sums, n_bins)
    x_bins = np.array([c.sum() for c in x_chunks]) / max(1.0, blob_area)
    y_bins = np.array([c.sum() for c in y_chunks]) / max(1.0, blob_area)
    return x_bins, y_bins


# ============================================================================
# FEATURE EXTRACTION PER MASK
# ============================================================================
def features_from_mask(mask, use_features, proj_bins,
                       keep_hu, min_hole_area):
    """Return dict of {feature_name: value} or None if mask unusable."""
    blob, blob_stat = largest_blob(mask)
    if blob is None:
        return None

    h, w = mask.shape
    crop_area = float(h * w)
    blob_area = float(blob_stat[cv2.CC_STAT_AREA])
    bw = float(blob_stat[cv2.CC_STAT_WIDTH])
    bh = float(blob_stat[cv2.CC_STAT_HEIGHT])

    feats = {}

    # (a) topological
    holes = find_holes(blob, min_hole_area)
    if "hole_count" in use_features:
        feats["hole_count"] = len(holes)

    # (b) connected components on the FULL mask
    if "connected_component_count" in use_features:
        n_cc, _, _, _ = cv2.connectedComponentsWithStats(mask, 8)
        feats["connected_component_count"] = n_cc - 1   # minus background

    # (c) blob area ratio
    if "blob_area_ratio" in use_features:
        feats["blob_area_ratio"] = blob_area / crop_area

    # (d) blob circularity (fallback)
    if "blob_circularity" in use_features:
        contours, _ = cv2.findContours(blob, cv2.RETR_EXTERNAL,
                                       cv2.CHAIN_APPROX_SIMPLE)
        per = cv2.arcLength(contours[0], True) if contours else 0.0
        feats["blob_circularity"] = (4*np.pi*blob_area / (per**2)) if per > 0 else 0.0

    # (e) blob aspect (fallback)
    if "blob_aspect" in use_features:
        feats["blob_aspect"] = bw / max(1.0, bh)

    # (f)-(h) hole-derived
    if holes:
        hx, hy, hw, hh, harea = max(holes, key=lambda s: s[cv2.CC_STAT_AREA])

        if "hole_area_ratio" in use_features:
            feats["hole_area_ratio"] = float(harea) / blob_area
        if "hole_aspect" in use_features:
            feats["hole_aspect"] = float(hw) / max(1.0, hh)
        if "hole_centroid" in use_features:
            blob_cx = blob_stat[cv2.CC_STAT_LEFT] + bw / 2.0
            blob_cy = blob_stat[cv2.CC_STAT_TOP]  + bh / 2.0
            hole_cx = hx + hw / 2.0
            hole_cy = hy + hh / 2.0
            feats["hole_centroid_dx"] = (hole_cx - blob_cx) / max(1.0, bw)
            feats["hole_centroid_dy"] = (hole_cy - blob_cy) / max(1.0, bh)
    else:
        if "hole_area_ratio" in use_features: feats["hole_area_ratio"] = 0.0
        if "hole_aspect"     in use_features: feats["hole_aspect"]     = 0.0
        if "hole_centroid"   in use_features:
            feats["hole_centroid_dx"] = 0.0
            feats["hole_centroid_dy"] = 0.0

    # (i) projections
    if "projections" in use_features:
        xb, yb = projections_binned(blob, proj_bins, blob_area)
        for i, v in enumerate(xb):
            feats[f"proj_x_{i}"] = float(v)
        for i, v in enumerate(yb):
            feats[f"proj_y_{i}"] = float(v)

    # (j) Hu moments (fallback, on the hole = numeral)
    #     PLACEHOLDER - implement only if the default set under-delivers.
    if keep_hu and holes:
        pass

    return feats


# ============================================================================
# MAIN LOOP
# ============================================================================
def build_features(mask_root, class_ids, out_csv,
                   use_features, proj_bins, keep_hu, min_hole_area):
    fieldnames = None
    rows = []

    for cid in class_ids:
        folder = os.path.join(mask_root, str(cid))
        if not os.path.isdir(folder):
            continue
        for fname in os.listdir(folder):
            if not fname.lower().endswith(".png"):
                continue
            mask = cv2.imread(os.path.join(folder, fname),
                              cv2.IMREAD_GRAYSCALE)
            if mask is None:
                continue
            mask = cv2.threshold(mask, 127, 255,
                                 cv2.THRESH_BINARY)[1]

            feats = features_from_mask(mask, use_features, proj_bins,
                                       keep_hu, min_hole_area)
            if feats is None:
                continue

            row = {"filename": f"{cid}/{fname}"}
            row.update(feats)
            rows.append(row)

    if rows:
        fieldnames = ["filename"] + sorted(
            k for k in rows[0].keys() if k != "filename")

    with open(out_csv, "w", newline="") as f:
        w = csv.DictWriter(f, fieldnames=fieldnames)
        w.writeheader()
        for r in rows:
            w.writerow(r)

    )

7. CODE DESCRIPTION
--------------------------------------------------------------------------------
cvtColor / threshold
  Loads the mask as grayscale and re-binarises at 127 so that a mask saved
  with any value in (0, 255) is treated as binary. Defensive.

largest_blob(mask)
  connectedComponentsWithStats labels every white region. The largest
  non-background component is the ball's white patch. All shape features
  are computed on this component, not on the raw mask.

find_holes(blob, min_area)
  Inverts the blob. Connected components of the inverse that do NOT touch
  the image border are holes (the numeral, plus any accidental inner white
  specks). Holes below min_area are dropped as noise.

projections_binned(blob, n_bins, blob_area)
  Column sums and row sums give the raw profile. array_split groups each
  profile into n_bins equal chunks; each chunk is summed. Divide by blob
  area to normalise. Result: two length-n_bins vectors representing the
  horizontal and vertical mass distribution of the blob.

features_from_mask(...)
  Coordinates the above. Every feature is guarded by an "if feature in
  use_features" test, so the fallback set is a one-line parameter change.

build_features(...)
  Iterates class folders under mask_png\. Writes one CSV row per mask.
  Rows whose mask is unusable (no blob) are silently skipped — these crops
  were already logged as rejects at 1.5.1, so no second log is needed.

8. REJECTED-CROP HANDLING
--------------------------------------------------------------------------------
1.5.1 rejected some crops (no usable numeral-region mask). Those crops have
no row in features.csv.

DEFAULT POLICY (b): leave splits.csv untouched. 1.5.3 joins by inner match.
  - splits.csv keeps all rows from 1.4.1.
  - 1.5.3 does features.csv INNER JOIN splits.csv on filename.
  - Rows in splits.csv with no match in features.csv are dropped silently.
  - No re-run of 1.4.1 needed.
  - Documented as a limitation only if rejection rate is non-trivial.

ALTERNATIVE (a): re-run 1.4.1 after 1.5.1, so splits.csv contains only
  surviving crops. Cleaner but requires re-running 1.4.2 verification.
  Adopt only if the rejection rate turns out to be large enough that the
  frozen splits.csv becomes misleading.

ALTERNATIVE (c): leave both as-is, document every dropped row individually
  in the report. Overkill for this project.

WHEN TO RECONSIDER: if 1.5.1 rejects more than ~10% of any single class,
  switch to (a). Otherwise (b) stands.

10. RESCALE / FALLBACK TRIGGERS
--------------------------------------------------------------------------------
- If default 23-feature set produces poor class separation in 1.6 EDA:
    -> try fallbacks (d) blob_circularity and (e) blob_aspect first.
    -> if still poor, add (j) Hu moments on hole.
    -> if still poor, consider dropping (i) projections and re-running
       EDA; projections are the most rotation-sensitive feature.
- If PROJECTIONS dominate the feature matrix (large magnitudes, all other
  features negligible in scatter plots):
    -> check normalisation; must divide by blob area, not by total pixels.
- If any class has fewer than 50 rows in features.csv after a full run:
    -> a class was hit hard by 1.5.1 rejection. Trigger 1.3.5 stride-3
       re-extraction and re-run the chain 1.3.2 -> 1.5.1 -> 1.5.2.
