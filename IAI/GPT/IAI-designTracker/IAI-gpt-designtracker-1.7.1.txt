--------------------------------------------------------------------------------
1. ESSENCE
--------------------------------------------------------------------------------
Two checks on the numeric feature table before scaling:

(a) MISSING VALUES
    Any NaN, None, or empty cells in the retained feature columns.
    Detect:  df.isna().sum() -> one number per column.
    If zero everywhere: nothing to fix. Document.
    If nonzero: do NOT impute. Trace back to the source. See section 7.

(b) OUTLIERS
    Values far outside the typical range for their column, usually caused
    by a bad crop, a failed mask, or an edge case in feature extraction.
    Detect:  IQR (recommended) or z-score.
    Handle:  clip, remove, or keep-and-document.

WHY IT MATTERS
    Scaling (1.7.2) is sensitive to extremes. A single blob_area_ratio = 50
    from a pathological mask can dominate StandardScaler's mean and std,
    squashing all other values into a narrow band. Outliers also distort
    SVM decision boundaries and inflate k-NN distances.

[R1] TWO SPECIAL FEATURE CLASSES - READ BEFORE TUNING OUTLIER DETECTION
    Before choosing IQR thresholds or a clip/remove policy, note that two
    groups of features in this dataset violate IQR's assumptions and must
    be handled separately:

    (i)  SMALL-CARDINALITY FEATURES
         hole_count               (values: {0, 1, 2})
         connected_component_count (small integers)
         IQR is often 0 for these columns. lower == upper == Q1. Every
         non-modal value is then flagged as an outlier, which would clip
         or delete the informative minority values.

    (ii) BOUNDED-SUM STRUCTURAL FEATURES
         proj_x_0..7 and proj_y_0..7
         By construction (1.5.2), each 8-bin group sums to 1. Clipping a
         single bin breaks the invariant: the vector no longer sums to 1,
         and downstream heatmap / distance interpretations from 1.6.3
         become invalid.

    These two classes are EXCLUDED from default cleaning. See sections 5
    and 6 for how the code and policy handle this.

    import os
    import sys
    import pandas as pd
    import numpy as np

    # ========================================================================
    # [PARAMETERS - FILL IN BEFORE RUN]
    # ========================================================================
    DATASET_CSV      = r"[DATASET_CSV]"       # ...\dataset.csv
    RETAINED_TXT     = r"[RETAINED_TXT]"      # ...\retained_features.txt
    OUT_DIR          = r"[OUT_DIR]"           # ...\billiards-game-clips
    LOG_PATH         = r"[LOG_PATH]"          # ...\logs\1.7.1_cleaning_report.txt

    # [R1] Features excluded from outlier detection.
    # Rationale:
    #   - discrete features: IQR often 0, would flag every minority value
    #   - projection bins: sum-to-1 invariant would break under clip
    EXCLUDED_FEATURES = [
        "hole_count",
        "connected_component_count",
        "proj_x_0", "proj_x_1", "proj_x_2", "proj_x_3",
        "proj_x_4", "proj_x_5", "proj_x_6", "proj_x_7",
        "proj_y_0", "proj_y_1", "proj_y_2", "proj_y_3",
        "proj_y_4", "proj_y_5", "proj_y_6", "proj_y_7",
    ]

    OUTLIER_METHOD   = [OUTLIER_METHOD]       # "iqr" | "zscore"
    IQR_K            = [IQR_K]                # 1.5
    ZSCORE_THR       = [ZSCORE_THR]           # 3.0
    CLIP_OR_REMOVE   = [CLIP_OR_REMOVE]       # "clip" | "remove" | "keep"
    MIN_IQR_FLOOR    = [MIN_IQR_FLOOR]        # 1e-6  (guard against IQR==0)

    # ========================================================================
    # TEE STDOUT TO LOG
    # ========================================================================
    os.makedirs(os.path.dirname(LOG_PATH), exist_ok=True)
    class Tee:
        def __init__(self, path): self.f = open(path, "w")
        def write(self, s): self.f.write(s); sys.__stdout__.write(s)
        def flush(self):     self.f.flush();   sys.__stdout__.flush()
    sys.stdout = Tee(LOG_PATH)

    # ========================================================================
    # LOAD
    # ========================================================================
    df = pd.read_csv(DATASET_CSV)
    retained = [line.strip() for line in open(RETAINED_TXT)
                if line.strip() and not line.startswith("#")]

    # [R1] Warn on typos silently dropped from retained_features.txt.
    missing_from_df = [f for f in retained if f not in df.columns]
    if missing_from_df:
        print(f"[WARNING] retained_features.txt names columns not in "
              f"dataset.csv: {missing_from_df}")
        print(f"[WARNING] These will be ignored. Fix the config and "
              f"re-run if unintended.")

    feats = [f for f in retained if f in df.columns]
    print(f"[INFO] Retained features loaded: {len(feats)}")
    print(f"[INFO] Excluded from outlier detection: {len(EXCLUDED_FEATURES)}")

    # [R1] Split the retained set into cleanable vs excluded.
    cleanable = [f for f in feats if f not in EXCLUDED_FEATURES]
    print(f"[INFO] Cleanable features: {len(cleanable)}")
    print(f"       {cleanable}")

    # ========================================================================
    # MISSING VALUES
    # ========================================================================
    X_all = df[feats]
    nan_counts = X_all.isna().sum()
    print("\nMissing values per column (retained set):")
    print(nan_counts)

    # ========================================================================
    # OUTLIERS - TRAIN ONLY FOR THRESHOLD DERIVATION
    # ========================================================================
    # [R1] Derive thresholds from TRAIN only. Applying the bounds to all
    # roles preserves the group-by-clip split integrity from 1.4.1.
    # Deriving from the full dataset would leak val/test information into
    # the cleaning decision.
    train_df = df[df["role"] == "train"]
    X_clean_train = train_df[cleanable]

    if OUTLIER_METHOD == "iqr":
        q1 = X_clean_train.quantile(0.25)
        q3 = X_clean_train.quantile(0.75)
        iqr = q3 - q1

        # [R1] IQR floor: guard against discrete features sneaking through
        # even if EXCLUDED_FEATURES is mis-configured. An IQR below the
        # floor is widened to the floor, preventing lower == upper.
        iqr_safe = iqr.clip(lower=MIN_IQR_FLOOR)

        if (iqr < MIN_IQR_FLOOR).any():
            warned = list(iqr[iqr < MIN_IQR_FLOOR].index)
            print(f"\n[WARNING] IQR near zero for: {warned}")
            print(f"          Widening to floor {MIN_IQR_FLOOR}. "
                  f"Check EXCLUDED_FEATURES.")

        lower = q1 - IQR_K * iqr_safe
        upper = q3 + IQR_K * iqr_safe

    else:
        mean = X_clean_train.mean()
        std  = X_clean_train.std()
        lower = mean - ZSCORE_THR * std
        upper = mean + ZSCORE_THR * std

    # Apply bounds to ALL roles (thresholds derived from train only).
    X_clean_all = df[cleanable]
    outlier_mask = (X_clean_all < lower) | (X_clean_all > upper)

    print("\nOutliers per cleanable column (bounds from train):")
    print(outlier_mask.sum())
    print("\nPer-column min / max / Q1 / Q3 (on train, cleanable only):")
    print(X_clean_train.describe().T[["min", "max", "25%", "75%"]])

    # ========================================================================
    # HANDLE
    # ========================================================================
    if CLIP_OR_REMOVE == "clip":
        df[cleanable] = X_clean_all.clip(lower=lower, upper=upper, axis=1)

        # [R1] Invariant check: projections excluded from clip, so they
        # should still sum to 1. Assert to catch future mis-configuration.
        proj_x_cols = [c for c in feats if c.startswith("proj_x_")]
        proj_y_cols = [c for c in feats if c.startswith("proj_y_")]
        if proj_x_cols:
            sx = df[proj_x_cols].sum(axis=1)
            assert np.allclose(sx, 1.0, atol=1e-3), \
                f"proj_x sum-to-1 invariant broken after clip " \
                f"(min={sx.min():.4f}, max={sx.max():.4f})"
        if proj_y_cols:
            sy = df[proj_y_cols].sum(axis=1)
            assert np.allclose(sy, 1.0, atol=1e-3), \
                f"proj_y sum-to-1 invariant broken after clip " \
                f"(min={sy.min():.4f}, max={sy.max():.4f})"

        df.to_csv(os.path.join(OUT_DIR, "dataset_clean.csv"), index=False)
        print("\nClipped cleanable columns; wrote dataset_clean.csv")

    elif CLIP_OR_REMOVE == "remove":
        keep = ~outlier_mask.any(axis=1)
        df[keep].to_csv(os.path.join(OUT_DIR, "dataset_clean.csv"),
                        index=False)
        print(f"\nRemoved {int((~keep).sum())} rows; wrote dataset_clean.csv")

    else:
        print("\nOutliers kept. Document in report section 3.")

    sys.stdout.flush()

5. RECOMMENDATIONS FOR THIS PROJECT
--------------------------------------------------------------------------------
MISSING VALUES
    Run the check. Expect zero. Document "no missing values" in §3.
    Reason: 1.5.2 returns 0.0 defaults instead of NaN; rows are only
    dropped at 1.5.1, and those never reach features.csv.

OUTLIER METHOD
    Use IQR with K=1.5. Do NOT use z-score.
    Reason: your features are not normally distributed. hole_count is a
    small integer (0/1/2); projections are bounded [0,1] and sum-
    constrained; blob_area_ratio is bounded by construction. Z-score
    assumes normality and will either miss outliers or flag non-outliers.

[R1] FEATURE CLASSES - HANDLING POLICY
    Three classes of feature, three policies:

    Class 1 - CONTINUOUS, UNBOUNDED
        blob_area_ratio, hole_area_ratio, hole_aspect, hole_centroid_dx,
        hole_centroid_dy
        Policy: standard IQR detection; clip or keep.

    Class 2 - DISCRETE / SMALL-CARDINALITY
        hole_count, connected_component_count
        Policy: EXCLUDED from outlier detection. Not clipped, not removed.
        Reason: IQR is unstable on these; minority values (e.g. a "2-hole
        numeral" in a dataset dominated by "1-hole") are legitimate signal,
        not noise.

    Class 3 - BOUNDED-SUM STRUCTURAL
        proj_x_0..7, proj_y_0..7
        Policy: EXCLUDED from outlier detection.
        Reason: clipping one bin breaks the sum-to-1 invariant. An outlier
        bin is not an error; it is a distribution shape.

    The EXCLUDED_FEATURES parameter encodes all of this. Only Class 1
    features are subject to IQR detection in R1.

HANDLING POLICY (Class 1 only)
    Prefer CLIP over REMOVE.
    Reason: clipping preserves all rows, compresses the tails without
    deleting data, and keeps the stratified split intact. Removing rows
    silently shifts class balance and can break the group-by-clip split.

    Or use KEEP-and-document if outliers are < 2% per column.
    Reason: reviewers accept "outliers retained and documented" more
    readily than silent deletion.

WHAT NOT TO DO
    - Do not use Isolation Forest or ML-based outlier detection. Overkill
      for 23 bounded features on ~500 samples.
    - Do not impute missing values. If NaN appears, that is a bug upstream
      at 1.5.2. Fix at the source; do not patch here.
    - [R1] Do not derive cleaning thresholds from val/test. If you clip or
      remove, derive thresholds from TRAIN ONLY, then apply to all roles.
      Otherwise the group-by-clip integrity from 1.4.1 is broken.
      This is now enforced in the code (train_df filter before quantile).
    - [R1] Do not clip the projection bins. Their sum-to-1 invariant is
      what makes them interpretable. See Class 3 above.
    - [R1] Do not clip small-integer counts. A minority value like "2" in
      hole_count is signal, not noise. See Class 2 above.

REPORT SURFACE (PRELIMINARY ML §3)
    One sentence naming the method and result:
    "Checked for missing values (none found) and outliers (IQR K=1.5 on
     continuous features only; discrete and projection-sum features
     excluded by design). N outliers detected across continuous features.
     Clipped at train-derived bounds. Distribution unaffected downstream."
    Plus: logs/1.7.1_cleaning_report.txt as supporting artefact.

    30 minutes of code, 15 minutes of reading, 1 paragraph in the report.

6. WHAT CAUSES MISSING VALUES
--------------------------------------------------------------------------------
Human / manual sources:
    - data entry errors (skipped fields)
    - non-response in surveys
    - deliberate omission (redaction, privacy)
    - transcription loss
    Not applicable to this project (machine-produced data).

Sensor / measurement sources:
    - sensor dropout mid-recording
    - out-of-range readings
    - corrupted video frames -> silent skip, no row written
    Partially applicable. cv2.VideoCapture.read() returning False causes
    the loop to skip, not to write NaN. Silent skip, not missing value.

Merge / join sources:
    - key mismatch on a join
    - left join with missing right side
    - schemas differ on concatenation
    Relevant. See section 7.

Computation sources:
    - divide by zero
    - log or sqrt of a negative number
    - mean() of an empty list
    - library defaults returning NaN
    Most relevant to this project. See section 7.

7. WHERE NaN WOULD COME FROM IN THIS PIPELINE
--------------------------------------------------------------------------------

    Divide-by-zero in features     | 1.5.2 features_from_mask    | NaN in

WHY THIS PIPELINE PROBABLY WILL NOT HAVE NaN
    1.5.2 returns None instead of NaN; caller skips the row.
    1.5.1 pre-filters empty masks via mask_is_usable().
    1.5.2 uses max(1.0, blob_area) guards on divisions.

WHAT TO DO IF NaN APPEARS
    1. Identify the column with NaN.
    2. Trace back to the 1.5.2 function producing it.
    3. Look for an unguarded division or an empty-list operation.
    4. Check whether 1.5.1's mask_is_usable() filter is working.
    5. Fix at the source, re-run 1.5.1 -> 1.5.2 -> 1.5.3.
    Do NOT impute at 1.7.1.

10. RESCALE / FALLBACK TRIGGERS
--------------------------------------------------------------------------------
    - NaN in any retained column:
        -> bug upstream at 1.5.2; fix at source; do NOT impute.
    - Any column with > 5% outliers:
        -> inspect a sample of offending rows; decide clip / remove.
    - Any role loses more than 5% of rows due to remove:
        -> prefer clip instead; removing shifts class balance and risks
           breaking the group-by-clip split.
    - ALL cleanable features show heavy tails (many outliers in every
      column):
        -> revisit 1.5.1 thresholds or 1.5.2 normalisation guards.
    - [R1] IQR near zero for any cleanable column:
        -> the feature likely belongs in EXCLUDED_FEATURES. Review
           cardinality and add it. See section 5 Class 2.
    - [R1] Projection sum-to-1 assertion fails after clip:
        -> EXCLUDED_FEATURES was mis-configured; projections were clipped.
           Restore the exclusion list and re-run. This is a code bug, not
           a data issue.

12. DESIGN DECISIONS - ALL CONFIRMED
--------------------------------------------------------------------------------
(a) Outlier method: IQR (K=1.5). Rejected: z-score (non-normal features).
(b) Handling: clip preferred; remove only on evidence; keep acceptable if
    outlier rate is low and documented.

CORRECTION 2 - DISCRETE FEATURES BREAK IQR (BLOCKING)
--------------------------------------------------------------------------------
WHERE IN R0:
    Section 4 - IQR applied uniformly to all retained features.

PROBLEM:
    hole_count and connected_component_count are small-cardinality
    integers. IQR is frequently 0. When IQR = 0, lower == upper == Q1,
    so EVERY non-modal value is flagged as an outlier. Clipping or
    removing these values destroys legitimate minority signal
    (e.g. a "2-hole" numeral in a dataset dominated by "1-hole").

FIX IN R1:
    Section 4:
        EXCLUDED_FEATURES = ["hole_count",
                             "connected_component_count", ...]
        cleanable = [f for f in feats if f not in EXCLUDED_FEATURES]
        iqr_safe = iqr.clip(lower=MIN_IQR_FLOOR)
    Discrete features are never touched by IQR detection.

SECTION REFERENCES:
    Section 1        - "[R1] TWO SPECIAL FEATURE CLASSES" preamble
    Section 3        - step 2 now splits cleanable vs excluded
    Section 4        - EXCLUDED_FEATURES parameter + IQR floor guard
    Section 5        - new "FEATURE CLASSES - HANDLING POLICY"
    Section 10       - new trigger for zero-IQR cleanable columns
    Section 12(i)    - "Feature classes" design decision

CORRECTION 3 - CLIPPING BREAKS PROJECTION SUM-TO-1 (BLOCKING)
--------------------------------------------------------------------------------
WHERE IN R0:

PROBLEM:

    a single bin is clipped, the vector no longer sums to 1. This
    invalidates:

        - distance metrics used by SVM/k-NN in Phase 2,
        - the structural-correlation argument in Preliminary ML §3.

FIX IN R1:
    Section 4:
        EXCLUDED_FEATURES includes all proj_x_* and proj_y_* names.
        After clip, an assertion verifies sum-to-1 for both groups.

SECTION REFERENCES:
