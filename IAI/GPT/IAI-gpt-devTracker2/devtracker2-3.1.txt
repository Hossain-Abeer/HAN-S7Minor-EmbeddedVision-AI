B - ESSENCE (what this step is)
--------------------------------------------------------------------------------

B.1 ONE-LINE
  Fit RF (locked params) on the full 245-row train set, save as one
  binary file, prove it reloads identically.

B.2 WHY PERSIST AT ALL
  Every step from 2.1 to 2.8 trained fresh. No single run saw all
  245 rows. Every script re-fit from scratch.
  From 3.2 onward, multiple scripts need THE SAME model object:
    - 3.2 must produce the test result
    - 4.1 must produce deploy predictions
    - 4.4 must measure deploy behaviour
  If each script re-trains, each produces a slightly different RF
  (same seed, but RF is stochastic across parallel jobs in some
  configurations; more importantly, re-fit = new thresholds on
  ties, new bootstrap order, etc). Deploy results would not match
  test results. TR7 (reproducibility) fails.

  Persisting ONCE breaks this: one file, consumed N times, all
  downstream numbers traceable to the same object.

B.3 WHAT GETS SAVED
  A single sklearn Pipeline object containing:
    ("scaler", StandardScaler())  <- fitted to train mean/std
    ("clf",    RandomForestClassifier)  <- 300 trees, thresholds,
                                            class weights, structure
  Serialised with joblib (pickle-based, faster for numpy-heavy objects).
  compress=3 keeps it ~1 MB.

  Alongside:
    feature names, ordered. Deploy scripts need this to arrange
    columns identically. Do not re-derive at consumption time -
    the model file should be self-contained.

B.4 THE RELOAD CHECK
  After save, load back into a new variable, predict 5 fixed rows,
  compare probability vectors elementwise.
  Assert max absolute difference < 1e-12.
  Failure => joblib wrote a corrupted or partial object.
  Success => save is byte-accurate, model is deployable.

  Why predict_proba not predict?
    predict returns 1 label. Two different models can agree on the
    label for a row by chance.
    predict_proba returns 15 probabilities per row. Matching all 15
    across 5 rows = 75 numbers. Far tighter test.

B.5 WHY train_f1 IS PRINTED AND EXPECTED AT 1.0
  Per 2.7, both candidates memorise the 245 training rows
  (rf train=1.000, svc train=0.991).
  So train macro-F1 = 1.0 after this fit is EXPECTED, not a surprise.
  It is a smoke check: if it drops below 0.95, something is wrong
  (wrong params, wrong data, wrong feature order). Real performance
  comes from test at 3.2, not from this number.

"""3.1 - Retrain final RF pipeline on full train set, persist to joblib."""

import sys, json
from pathlib import Path
import numpy as np
import joblib
from sklearn.ensemble import RandomForestClassifier

sys.path.insert(0, str(Path(__file__).parent))
import config
from pipeline import build_pipeline
from load_dataset import load_splits, load_retained_features

DATA_ROOT  = Path(config.DATA_ROOT)
MODELS_DIR = DATA_ROOT / "models"
LOGS_DIR   = Path(config.LOGS_DIR)
MODELS_DIR.mkdir(parents=True, exist_ok=True)
LOGS_DIR.mkdir(parents=True, exist_ok=True)

SEED = 42

MODEL_PATH  = MODELS_DIR / "3.1-final_pipeline.joblib"
FEAT_PATH   = MODELS_DIR / "3.1-final_feature_names.json"
LOG_PATH    = LOGS_DIR   / "3.1-finalize.txt"


def load_locked_params():
    p = MODELS_DIR / "2.6_selected_model.json"
    data = json.loads(p.read_text())
    return data["model"], data["params"]


def build_final_estimator(params):
    return RandomForestClassifier(
        n_estimators=params["n_estimators"],
        max_depth=params["max_depth"],
        min_samples_leaf=params["min_samples_leaf"],
        class_weight="balanced",
        random_state=SEED,
        n_jobs=-1,
    )


def main():
    log = []
    def emit(s):
        print(s)
        log.append(s)

    X_tr, y_tr, *_ = load_splits()
    feat_names = list(load_retained_features())
    emit(f"train shape  : {X_tr.shape}")
    emit(f"features     : {len(feat_names)}")

    name, params = load_locked_params()
    emit(f"locked model : {name}")
    emit(f"locked params: {params}")
    assert name == "rf", f"expected rf, got {name}"

    pipe = build_pipeline(build_final_estimator(params))
    pipe.fit(X_tr, y_tr)
    emit(f"pipeline fit : OK")

    probe = X_tr[:5]
    pred_before = pipe.predict_proba(probe)

    joblib.dump(pipe, MODEL_PATH, compress=3)
    FEAT_PATH.write_text(json.dumps(feat_names, indent=2))
    emit(f"wrote        : {MODEL_PATH}")
    emit(f"wrote        : {FEAT_PATH}")

    pipe2 = joblib.load(MODEL_PATH)
    pred_after = pipe2.predict_proba(probe)
    diff = float(np.max(np.abs(pred_before - pred_after)))
    emit(f"reload delta : {diff:.2e}")
    assert diff < 1e-12, f"reload mismatch: {diff}"
    emit("reload check : PASS")

    from sklearn.metrics import f1_score
    train_f1 = f1_score(y_tr, pipe.predict(X_tr), average="macro")
    emit(f"train f1     : {train_f1:.4f}  (expected near 1.0, per 2.7)")

    LOG_PATH.write_text("\n".join(log))
    print(f"\nwrote        : {LOG_PATH}")


if __name__ == "__main__":
    main()

E - SKELETAL EXPLANATION
--------------------------------------------------------------------------------

load_locked_params() -> (name: str, params: dict)
  [PARAM] none
  [DESC]  Reads models/2.6_selected_model.json.
          Returns ('rf', {'max_depth':10, 'min_samples_leaf':1,
                          'n_estimators':300}).
          Single source of truth. No hard-coding, no re-derivation.

build_final_estimator(params: dict) -> RandomForestClassifier
  [PARAM] params : dict with max_depth, min_samples_leaf, n_estimators
  [DESC]  Instantiates RF with locked params + class_weight='balanced'
          + seed=42 + n_jobs=-1.
          class_weight and seed match 2.1/2.4 exactly. The fitted
          forest is therefore the same class of object that was
          scored in CV - no silent drift between tuning and
          deployment.

main():
  [PARAM] none
  [DESC]  Sequence:
            1. Load X_train (245x15), y_train (245), feature_names.
            2. Read locked model + params from 2.6 JSON.
            3. Assert model name == 'rf'.
            4. build_pipeline(RF) -> Pipeline([StandardScaler, RF]).
            5. Fit on full 245 rows.
            6. Save pipeline via joblib(compress=3).
            7. Save feature names JSON.
            8. Reload pipeline, re-predict 5 fixed rows,
               assert max abs diff < 1e-12.
            9. Compute train macro-F1 (expected ~1.0 per 2.7).
           10. Write log.

DESIGN CHOICES
  joblib.compress=3
    300-tree RF on 15 features ~ few MB raw. compress=3 shrinks to
    <1 MB with no measurable load cost. Cheap win for repo hygiene.

  Separate feature_names JSON
    Deploy scripts must build X with the EXACT same column order that
    training used. Re-deriving from retained_features_correlations.txt
    at deploy time risks drift if that file is ever touched. The
    model file should be self-contained: joblib + this JSON is one
    consumable unit.

  Reload check via predict_proba not predict
    predict returns 1 label per row - too coarse, could match by
    chance. predict_proba returns 15 probabilities x 5 rows = 75
    numbers. Identity across 75 floats is a real test.

  Threshold 1e-12
    Machine precision. Anything larger means joblib corrupted the
    object on write. This is the tightest defensible assertion.

  train_f1 printed but not asserted to a tight bound
    Per 2.7, train macro-F1 = 1.0 is expected, not a quality metric.
    A loose sanity floor (implicit: if it drops below ~0.9, params
    or feature order is wrong). Real number comes at 3.2.
