B.4 WHY RF WINS ON THIS DATA (3 concrete reasons, no general claim)

  Reason 1 - Correlated features neutralised.
    The 15 retained features include 13 projection bins.
    Projection bins are structurally correlated: the 8 x-bins sum to 1,
    the 8 y-bins sum to 1. Pairwise |r| up to 0.77 observed at 8.3.
    SVC and k-NN measure distance in all 15 dims jointly -> correlated
    bins effectively double-count.
    RF samples a random feature subset per split -> correlation is
    neutralised. Some trees see proj_x_2, others see proj_y_3.
    This is the dominant reason.

  Reason 2 - Sparse extreme values defanged.
    proj_x_0 and proj_y_6 have training std ~0.01.
    After StandardScaler, several rows reach |scaled| > 5.
    RBF-SVC is heavily sensitive to extreme coordinates (kernel is
    exp(-gamma * dist^2)). One coordinate at 5 dominates the kernel.
    k-NN distance is equally distorted.
    RF only uses a feature at a split if it produces a clean gain.
    Outlier coordinates are effectively ignored unless useful.

  Reason 3 - Class_weight='balanced' applies per-tree.
    300 trees, each bootstrap-sampled with class reweighting.
    Minority classes (C5, C10 at 5 samples each) still appear as
    splits across the forest. Class 5's 5 samples are seen by many
    trees, not just one boundary.
    SVC's balanced weighting affects one global boundary per class;
    k-NN has no such mechanism.

SECTION C - TEACHING RECORD (foundations explained during 2.1/2.2)
--------------------------------------------------------------------------------

C.1 WHAT A MODEL IS
  A model is a RULE. Training adjusts the rule's internal parameters
  so it answers correctly on training data. Prediction applies the
  rule to new data.

  Every model type is a different SHAPE of rule:
    SVC  : curved boundary through 15-D space; params = kernel
           centre + width + class weights
    k-NN : "compare to k nearest stored rows, vote"; params = the
           stored rows themselves (memorisation)
    RF   : 300 decision trees, majority vote; params = every threshold
           in every tree

C.2 WHAT TRAINING DOES
  Training = search for parameter values that make the rule answer
  correctly on the training data.
  With 245 rows x 15 features, the search space is huge. The training
  algorithm navigates it. After training, parameters are fixed and the
  rule is finished.

C.3 WHY 3 MODELS, AND WHY THESE 3
  Rubric requires model comparison. 3 different philosophies:
    k-NN : instance-based (memorise, then nearest-neighbour vote)
    SVC  : boundary-based (draw cleanest curved separator)
    RF   : ensemble-based (300 trees voting)
  All handle 15 classes natively, all CPU-cheap, no GPU.
  Rejected alternatives: decision tree alone (high variance),
  logistic regression (linear boundary - insufficient),
  naive Bayes (assumes feature independence - false here).

C.4 ACCURACY
  accuracy = correct predictions / total predictions
  Single number. Simple. MISLEADING under class imbalance.
  A model that always predicts class 1 gets 43/245 = 17.5% accuracy
  on your train set. Zero information, non-zero score.

C.5 PRECISION AND RECALL (per class)
  precision_X = TP / (TP + FP)
      "when model says X, how often is it right?"
  recall_X    = TP / (TP + FN)
      "of all true X, how many did the model find?"
  Trade-off: high precision = few false alarms; high recall = few misses.

C.6 F1 (per class)
  F1_X = 2 * precision_X * recall_X / (precision_X + recall_X)
  Harmonic mean. Punishes imbalance between precision and recall.
  One number per class. Computed 15 times for this project.

C.7 MACRO-F1
  macro-F1 = (F1_1 + F1_2 + ... + F1_15) / 15
  Plain average across all 15 classes.
  Rewards every class equally, including the thin ones (C5, C10).
  This is the SMART objective metric.

  Alternatives:
    weighted-F1 = averages weighted by class size -> hides thin-class
                  failure. NOT used.
    micro-F1    = global TP/FP/FN -> basically accuracy for single-
                  label problems. NOT used.

C.8 WORKED EXAMPLE (small, conceptual)
  Assume 3 classes, 6 test rows:
    True:  [1, 1, 1, 2, 2, 3]
    Pred:  [1, 1, 2, 2, 3, 1]
  Class 1: TP=2, FN=1, FP=1 -> P=0.667, R=0.667, F1=0.667
  Class 2: TP=1, FN=1, FP=1 -> P=0.5,   R=0.5,   F1=0.5
  Class 3: TP=0, FN=1, FP=1 -> P=0.0,   R=0.0,   F1=0.0
  macro-F1 = (0.667 + 0.5 + 0.0) / 3 = 0.389
  F1 is arithmetic on the prediction table, not a stored entity.

C.9 CROSS-VALIDATION
  One split -> one roll of the dice. Lucky/unlucky folds give
  misleading scores.
  k-fold CV: split training rows into k folds. Train on k-1, validate
  on held-out. Rotate. Each row gets exactly one turn as validation.

  STRATIFIED k-fold: each fold preserves class proportions.
  Critical under 8.6:1 imbalance - plain k-fold might put both C10
  samples in one fold, starving the other folds of that class.

  In this run: StratifiedKFold(n_splits=5, shuffle=True, random_state=42).
  Each fold ~49 rows from the 245-row training set.

C.10 WHAT std MEANS
  std = fold-to-fold variation of the metric.
  f1_macro = 0.7191 +/- 0.0865:
    mean = typical performance across folds
    std  = how much folds disagree
  Wide std on small data is expected. 245 rows total, 5 folds of ~49.
  One fold with a bad thin-class draw moves the mean.

  Practical consequence: tuning improvements below std are noise, not
  signal. Applies to 2.3 grid search sizing (see B.6).

C.11 DATA FLOW LINKING F1 AND RF
  Train phase:
    245 rows (15 numbers + true label) -> feed to RF -> parameters
    adjusted -> trained model in memory.

  CV score phase:
    For fold 1..5:
      train model on 4 folds (~196 rows)
      predict labels for held-out fold (~49 rows)
      compare predictions to true labels -> prediction table
      compute per-class precision, recall, F1 -> 15 numbers
      average those 15 numbers -> macro-F1 for this fold
    Collect 5 macro-F1s -> mean, std.

  Chain:
    training rows -> model -> predictions on held-out rows
                  -> comparison to truth
                  -> per-class F1 -> macro-F1 -> one number per model.

  RF PRODUCES predictions. F1 SCORES them. They are not linked in any
  stored artefact - F1 is computed at fold end and discarded.
