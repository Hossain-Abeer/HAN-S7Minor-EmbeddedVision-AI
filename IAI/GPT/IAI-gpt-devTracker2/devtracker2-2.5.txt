C - ROOT CAUSE - VAL DISTRIBUTION SHIFT (clip 5)
--------------------------------------------------------------------------------

C.1 THE FINDING
  Every clip-5 crop is visually ~2x larger than the equivalent
  clip-1..4 crop for the same class.

  Evidence (from directory listing):
    Class 1: clip1-4 avg ~4500 B, clip5 avg ~8000 B  (1.8x)
    Class 9: clip1-4 avg ~4500 B, clip5 avg ~8300 B  (1.8x)
    Class 14: clip1-4 avg ~4600 B, clip5 avg ~8400 B (1.8x)
    Class 15: clip1-4 avg ~4500 B, clip5 avg ~8500 B (1.9x)

  Confirmed by user visual inspection:
    unsorted_png\9\clip1_frame000029_ball3.png
    unsorted_png\9\clip5_frame000059_ball4.png
    -> clip 5 crop is significantly larger.

C.2 MECHANISM
  Features extracted at 2.5 are scale-dependent:
    blob_area_ratio       = blob pixels / crop pixels
    connected_component_count (partly scale-dependent at boundary)
    projections_binned    = column/row sums normalised by blob_area

  Training crops (clips 2-4) at one scale -> the models learned
  feature patterns at THAT scale.
  Val crops (clip 5) at ~2x scale -> feature values shift.
  The classifier produces predictions fitted to a scale it never
  saw. Accuracy collapses.

C.3 HOW THE SPLIT CAUSED THIS
  From 5.2: rank 0 -> val, rank 1 -> test, rest -> train.
  Ranked by (classes_covered, min_count).
  Clip 5 had covered=15, min_count=2 -> rank 0 -> val.
  The split was chosen for COVERAGE.
  It was not chosen for VISUAL CONSISTENCY across clips.
  No post-split check verified that val feature distributions
  match train feature distributions.

C.4 WHY THE 8.3 / 9.2 EDA DIDN'T CATCH IT
  EDA at 8.2 and 9.2 was performed on TRAIN rows only
  (role == "train" filter).
  The distribution difference between train and val was never
  plotted side-by-side.
  This is a real gap in the EDA design, documented as L17.

C.5 LIKELY PHYSICAL CAUSES (any combination)
  - Clip 5 recorded at different camera zoom
  - Clip 5 recorded at different render resolution
  - Clip 5 from a different game build
  - Clip 5 shorter scene, motion gate fired on closer ball clusters

  Root-cause not fully diagnosable without per-clip frame review.
  The effect is what matters; the mechanism is documented.

C.6 TENNIS ANALOGY (teaching)
  You train a classifier on standard-size tennis balls.
  At test time you give it ping-pong balls.
  The classifier is not wrong. The input is not what it was trained on.
  Distribution shift is the input changing under a fixed model.


--------------------------------------------------------------------------------
D - TEACHING - CV VS VAL, DISTRIBUTION SHIFT
--------------------------------------------------------------------------------

D.1 WHAT CV MEASURES
  "Can the model generalise within the training distribution?"
  Train rows are split into 5 folds. Each fold is a random sample
  of train. So CV answers: "if I hold out part of train, will my
  model still work on the rest of train?"

  CV cannot warn you about data that is outside train's distribution.

D.2 WHAT VAL MEASURES
  "Can the model generalise to a new dataset?"
  Val is 128 crops from clip 5. Not in train. Fitted never.
  Val answers: "does the model work on data it has never seen?"

  IF val is drawn from the same distribution as train, val is a
  clean generalisation test.
  IF val is drawn from a different distribution, val measures
  distribution shift, NOT model quality.

D.3 WHAT DISTRIBUTION SHIFT MEANS
  Train inputs come from distribution P_train.
  Val inputs come from distribution P_val.
  If P_val != P_train, the model was trained for the wrong game.

  Test: are inputs at prediction time drawn from the same
  distribution as training?
    Yes -> model performance generalises as CV predicted.
    No  -> model performance collapses by an amount proportional
           to the shift.

  Your case: P_val != P_train by a scale factor of ~2.

D.4 WHY THE DROP IS ~0.36 AND NOT ~0.72
  If the model was COMPLETELY blind to val, macro-F1 would be ~0
  (random among 15 classes).
  0.30-0.34 means partial signal survives. Large-crop ball numerals
  still share some shape characteristics with small-crop numerals,
  just not enough for clean classification.
  Some classes (1, 5, 7, 11, 15) are distinctive enough to survive
  the scale change. Others (2, 4, 8, 9, 10, 13) are not.

D.5 THE F1-ZERO PATTERN MAKES SENSE NOW
  Classes with F1=0 on val are mostly thin ones OR ones prone to
  confusion (4 vs 3, 9 vs 14). Scale shift amplifies both problems.
  Classes with high val F1 are the numerically distinct ones
  (1, 5, 7, 11, 15 — all have distinctive shapes or solid/stripe
  markers visible even at wrong scale).

D.6 RANK STABILITY - WHY IT MATTERS
  All 3 models collapse on val, but the ORDER of collapse is
  the same as CV: rf > svc > knn.
  This means:
    (a) The comparison between models is robust to shift.
    (b) RF's advantage is not a CV artefact.
    (c) If we had to pick a model without val, CV would have
        given the same answer as val.

  This is why we can still trust CV for 2.6 selection despite
  val being invalid as an absolute score.

D.7 WHAT WE COULD HAVE DONE TO PREVENT THIS
  - Visual consistency check at split time: compare mean crop
    size per clip before assigning roles.
  - Feature distribution comparison between roles after 7.3.
  - Stratified-by-scale split rather than stratified-by-class.

  All are good practice for future projects. Not action items
  now - the split is done, and re-splitting would leak through
  the analysis already completed.

D.8 WHAT WE MUST NOT DO NOW
  - Do NOT retune on val. Val is now known-unrepresentative.
  - Do NOT re-split. That would be data manipulation.
  - Do NOT retrain including val. Val's scale is wrong; it would
    drag the model toward clip-5 scale.
  - Do NOT discard val. Report it as an honest finding.

F - NEW LIMITATIONS FOR LEDGER
--------------------------------------------------------------------------------

L16 - VAL DISTRIBUTION SHIFT (CLIP 5)

  The group-by-clip split assigned clip 5 to val for class
  coverage reasons. Post-hoc inspection shows clip 5 crops are
  visually ~2x larger than train/test crops, likely due to a
  different capture zoom or render scale.

  Consequence: all three classifiers drop ~0.36 macro-F1 on val,
  far exceeding CV noise (0.086). Val macro-F1 is 0.31-0.34
  versus CV 0.66-0.72.

  This is a val-only defect. Test (clip 1) matches train scale
  and remains a valid hold-out. All model selection decisions use
  CV macro-F1, not val macro-F1. This limitation does not
  invalidate the model or the pipeline; it invalidates val as a
  selection signal.

  Documented in Full ML Section 6 + 8.

L17 - EDA DID NOT INCLUDE PER-ROLE FEATURE COMPARISON

  Feature distributions at 8.2 were computed on role == "train"
  only. No side-by-side comparison of train vs val vs test feature
  distributions was produced. This is why the clip-5 scale
  difference was not detected until val evaluation at 2.5.

  Future work: a per-role feature distribution comparison after
  role assignment would catch this class of problem early.
  Documented in Full ML Section 8 (future improvements).
