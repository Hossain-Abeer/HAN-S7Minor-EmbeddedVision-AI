C.1 WHAT HAPPENED

  The classical ML pipeline built at 2.1-3.1 achieved 0.7193 CV
  macro-F1 on training distribution, but only 0.2607 on the sealed
  test set. That is below the SMART target of 0.50 by 0.239.

  Both held-out sets (val clip 5, test clip 1) collapsed relative
  to train (clips 2-4). Failure is systematic across clips.

C.2 WHY THIS IS NOT A BUG

  - One-shot prediction discipline was followed (single .predict).
  - Feature order verified (model order == data order).
  - Persisted pipeline reloaded without error (3.1 reload delta
    0.00e+00).
  - 6/6 artefacts emitted correctly.
  - Test set was genuinely unseen by any prior step.

  The failure is a real property of the pipeline + data, not an
  execution error.

C.3 WHY THIS IS NOT A REASON TO RETUNE

  - 3.2 rule: one pass. Whatever number comes out is reported.
  - Retuning on test would convert the sealed test into a validation
    set, invalidating its status as held-out.
  - Re-splitting would leak through the analysis already completed.
  - The rubric rewards honest limitation documentation, not
    hidden failure.

C.4 WHY THIS MAKES THE REPORT STRONGER

  Rubric explicitly states:
    "Document limitations ... rather than conceal them."
    "Where a target is not met, the reason is recorded as a
     documented limitation."

  Three benefits of honest failure:
    1. Section 6 becomes credible. A model-selection chapter that
       reports 0.72 CV and 0.26 test honestly is more trustworthy
       than one that hides the gap or manipulates the split.
    2. Section 8 has real content. "Results vs SMART" becomes a
       diagnosis, not a victory lap. Higher-quality answer.
    3. Phase 4 (DL) is justified. A CNN with augmentation is the
       planned recovery mechanism. A 0.26 baseline is a more
       interesting starting point than 0.72 - the CNN story becomes
       "classical features collapse under distribution shift;
       augmentation-aware CNN recovers to X."

C.5 ROOT CAUSE DIAGNOSIS

  Three independent causes, all confirmed by the confusion matrix:

  (a) Feature scale sensitivity.
      blob_area_ratio and projection bins are ABSOLUTE measurements.
      Ball crop scale varies across clips (L16 confirmed for clip 5;
      now clip 1 also shows its own drift). The model learned feature
      patterns at the clip 2-4 scale; when scale drifts, the
      patterns shift.

  (b) RF decision-region collapse.
      Tree splits that worked on train cluster into a dense corner
      under shifted inputs. Visible as the class-12 magnet:
      precision 0.231, recall 1.000. Shifted inputs collapse into
      one leaf-rich region.

  (c) Structural thin + overlap classes.
      Classes 9, 10, 13 fail on BOTH val and test. These are:
        - 9 : 7 train samples, overlaps with 6 (rotation ambiguity)
        - 10: 5 train samples, thin
        - 13: 7 train samples, overlaps with 12 by shape
      Volume + shift both hurt these. They are the classical-ML
      ceiling on this data. Confirmed L5/L6/L7 known limitations.

C.6 WHY CV DID NOT PREDICT THIS

  CV splits train ROWS into folds. All folds come from clips 2, 3, 4.
  CV answers: "does the model generalise WITHIN clips 2-4?"
  It cannot detect that clip 1 or clip 5 is drawn from a different
  distribution because clips 1 and 5 were excluded from train.

  This is a structural property of group-by-clip splits: the
  "training distribution" is clips 2-4 only. Generalisation to other
  clips is a separate question that CV cannot answer.

C.7 WHAT THIS MEANS FOR L16

  L16 as originally stated (2.5):
    "val (clip 5) has distribution shift; test (clip 1) matches
     train scale."
  This was WRONG. Test does not match train scale. Test also shifts.

  L16 revised (for Section 8):
    "All three held-out clips (1, 5) show measurable distribution
     shift from the train clip cluster (2, 3, 4). The shift is not
     uniform: classes with distinctive shape or strong solid/stripe
     markers survive; scale-sensitive and overlap-prone classes
     fail. Test (clip 1) 0.2607 macro-F1 < val (clip 5) 0.3425
     macro-F1 < CV 0.7193.

     Distribution shift is universal across held-out clips on this
     dataset. The sealed test set is the honest measure of that."

SECTION D - TEACHING RECORD

D.1 WHAT "SEALED TEST SET" MEANS

  A sealed test set is data no model has ever been fit on or
  predicted on. From the moment of split (5.3) to the moment of
  test (3.2), no .fit() and no .predict() touches the test rows.

  Why: the honest test result must be a first measurement, not a
  re-measurement. If any script had fit on test, or tuned against
  test, the "one-shot test result" would be contaminated. It would
  no longer measure generalisation; it would measure how well the
  model was tuned to the test set.

D.2 WHAT 3.2 VERIFIED ABOUT THE SEAL

  - 3.1 finalize_model.py used X_tr only (asserted).
  - 2.7 learning_curve.py used X_tr only.
  - 2.8 scaler_compare.py used X_tr only.
  - 2.5 evaluate_val.py used X_tr (fit) + X_va (predict). No X_te.
  - 2.4 grid_search.py used X_tr only.
  - 2.2 train_models.py used X_tr only.

  The only script that has ever touched X_te is 3.2 itself. Seal intact
  until the one-shot call inside evaluate_once().

D.3 WHY THE RESULT IS A FINDING, NOT A FAILURE OF THE DEVELOPER

  A properly-built pipeline can legitimately fail to generalise.
  That is what happened here. The failure diagnoses a property of
  the data + features, not a mistake in the code. The rubric rewards
  this diagnosis.

  Contrast:
    - Undisciplined process: test fails -> retune -> test again ->
      test leaks -> report "0.72 test, great!" -> invalid.
    - Disciplined process: test fails -> report 0.26 -> diagnose
      cause -> document -> next phase targets the cause.

D.4 WHAT DISTRIBUTION SHIFT MEANS HERE

  The training distribution is clips 2, 3, 4. The model learned
  feature patterns within that distribution. Clips 1 and 5 are
  drawn from a different distribution:
    - Different zoom/render scale (L16)
    - Different crop sizes (2x on clip 5; smaller drift on clip 1)
    - Different ball positions / arrangements / capture conditions

  Under shift, the model's trained decision boundaries no longer
  align with the new data's structure. Predictions collapse.

D.5 WHY CV CANNOT DETECT THIS

  Cross-validation splits training rows into folds. Every fold
  comes from clips 2-4. So every fold has the SAME clip-scale
  distribution as the other folds.

  CV measures: "does the model generalise within clips 2-4?"
  It CANNOT measure: "does the model generalise to a different
  clip?"

  This is not a defect in CV. It is a structural limit of any
  split that does not include the shift axis. Group-by-clip
  guarantees that the shift axis is exactly what the split
  excludes from train.

D.6 WHY "TRAIN TRACKS CV" WAS THE EXPECTATION IN 3.1

  In 3.1's carry-forward, the expectation was:
    "Test is clip 1, matches train scale (L16 does not apply)."
  This assumption was WRONG. Clip 1 does NOT match train scale. It
  was based on limited inspection at 2.5.

  In retrospect, the correct expectation should have been:
    "Any clip not in train is a distribution test. Expect CV
     performance only if that clip's scale/arrangement matches
     clips 2-4. If it does not, expect collapse."

  Lesson: "held-out" is not the same as "same distribution."
  Always check.

D.7 WHY WE REPORT FAILED SMART HONESTLY

  The rubric explicitly says: "Meeting all acceptance criteria is
  required to pass. See the Course Overview guide for what
  distinguishes stronger work."

  Reaching SMART target is one criterion. DOCUMENTING the reason
  for not reaching it is another. A report that hides a 0.26 test
  result behind "we achieved 0.72 CV" fails the honest-documentation
  criterion. A report that states 0.26 and diagnoses the reason
  satisfies both criteria: measurable outcome (0.26 reported) +
  documented limitation (diagnosis given).

D.8 WHAT CAN AND CANNOT BE RECOVERED NOW

  CAN be recovered:
    - Honest reporting of the failure.
    - Diagnosis of the cause.
    - Structural class-level analysis (9, 10, 13 thin; 12 as
      prediction magnet).
    - Justification for Phase 4 recovery via CNN.

  CANNOT be recovered:
    - Higher test macro-F1. That number is set.
    - Retuning on test. That would break the seal.
    - Re-splitting. That would invalidate the analysis pipeline.
    - Concealing the failure. That would fail the honest-
      documentation criterion.

D.9 THE MOST IMPORTANT SENTENCE FOR THE REPORT

  "The classical-ML pipeline achieved CV macro-F1 = 0.7193, but
   one-shot test macro-F1 = 0.2607. The SMART objective was not met.
   Diagnosis: the 15-feature pipeline is scale-sensitive and does not
   generalise across clips; three classes (9, 10, 13) fail for
   structural reasons independent of shift. The phase-4 CNN with
   augmentation is the planned recovery path."

  Four claims, one paragraph. Complete picture. Nothing hidden.
