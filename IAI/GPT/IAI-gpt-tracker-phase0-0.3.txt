0.3.2 IDE CONFIGURATION (VS CODE)
--------------------------------------------------------------------------------

IDE
- Visual Studio Code, installed.

INTERPRETER SELECTION - PROBLEM FOUND
- `Python: Select Interpreter` listed:
    CPython 3.14.7 (uv)                -> not ours
    Python 3.14.7  (uv)                -> not ours
    Python 3.11.9  C:\dev\python311\   -> GLOBAL base, not venv
- The venv at C:\dev\envs\IAI-env\ was NOT auto-discovered.
- Reason: VS Code auto-discovers venvs INSIDE the workspace folder only.
  Our venv lives OUTSIDE (C:\dev\envs\), by deliberate design (see notes on
  0.1.1 and 0.1.2-0.1.3).

INTERPRETER SELECTION - FIX (RECOMMENDED: Option B)
Option A (per-session):
    Ctrl+Shift+P -> Python: Select Interpreter
    -> Enter interpreter path...
    -> C:\dev\envs\IAI-env\Scripts\python.exe

Option B (permanent, workspace-level, RECOMMENDED):
    Create .vscode/settings.json inside the repo:

    {
      "python.defaultInterpreterPath":
        "C:\\dev\\envs\\IAI-env\\Scripts\\python.exe"
    }

    Restart VS Code. Settings travel with the repo across both laptops,
    matching the sync workflow.

VERIFY INTERPRETER
- Bottom-right status bar shows interpreter; should read
  "Python 3.11.9 ('IAI-env')" or similar (venv name present).
- Or open a .py, run Python: Show Output, confirm the path.

WHY VENV IS OUTSIDE PYTHON311 (rationale recap)
1. Separation of concerns: interpreter (immutable) vs env (disposable).
2. One base, many venvs: C:\dev\envs\<project>-env for each project.
3. py install --target produces a MINIMAL bundle (python.exe only).
   Adding a venv inside would mix runtime files with project state.
4. Safe delete/rebuild: rmdir env; base Python untouched.
5. Username-free absolute paths on both laptops.
6. Unified C:\dev\ namespace:
       C:\dev\
       ├── python311\      (runtime)
       ├── envs\
       │   └── IAI-env\    (venv)
       └── IAI-data\       (dataset)
   Copy-paste C:\dev\ -> whole toolchain travels.
