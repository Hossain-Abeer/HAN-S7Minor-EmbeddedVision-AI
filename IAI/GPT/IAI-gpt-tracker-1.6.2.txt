PURPOSE OF THIS SECTION

--------------------------------------------------------------------------------
0.1 WHAT IS 1.6.2, AT THE TOP LEVEL?
--------------------------------------------------------------------------------
It is a VISUAL INSPECTION step.

You now have dataset.csv - one row per surviving crop, with 23 numeric
columns describing the shape of its numeral mask, plus a class label
(1-15) and a role (train/val/test).

1.6.2 asks, for each of the 23 features: does it actually look different
across the 15 classes?

  - If yes: the feature is useful.
  - If all 15 classes look the same on that feature: it is dead weight.

--------------------------------------------------------------------------------
0.2 WHAT IS A BOXPLOT?
--------------------------------------------------------------------------------
A boxplot is a compact graph of a distribution. For one feature and one
class:

  - The BOX spans the middle 50% of the values (25th to 75th percentile).
  - The LINE inside the box is the median.
  - The WHISKERS extend up/down to roughly the min and max (excluding
    outliers).
  - DOTS mark outliers.

So a boxplot answers: "for class 3, what range does this feature take?
Where is the middle? Is it tight or spread?"

--------------------------------------------------------------------------------
0.3 WHY COMPARE BOXES ACROSS CLASSES?
--------------------------------------------------------------------------------
A boxplot of one feature across 15 classes puts 15 boxes side-by-side.
You look at them and ask:

  - Do the boxes sit at DISTINCT HEIGHTS? -> the feature separates
    classes. Good.
  - Do the boxes OVERLAP HEAVILY?         -> the feature does not separate
    classes. Weak or dead.

This is the single most important EDA step for the Preliminary ML report:
it is the visual proof of "informative" and "discriminating."

--------------------------------------------------------------------------------
0.4 WHAT ARE THE 23 FEATURES?
--------------------------------------------------------------------------------
From 1.5.2, they describe the numeral's white-patch geometry:

  hole_count                 - how many enclosed holes the numeral patch
                               has. "8" -> 2 holes; "0"/"6"/"9" -> 1;
                               most digits -> 0.
  connected_component_count  - how many white blobs the mask splits into.
  blob_area_ratio            - size of white patch / crop area.
  hole_area_ratio,
  hole_aspect,
  hole_centroid_dx,
  hole_centroid_dy           - geometry of the largest hole (the numeral).
  proj_x_0..7, proj_y_0..7   - 16 values describing how the white mass is
                               distributed horizontally and vertically
                               (like a coarse silhouette).

Total: 1 + 1 + 1 + 1 + 1 + 2 + 16 = 23.

--------------------------------------------------------------------------------
0.5 WHY FILTER TO role == "train" ONLY?
--------------------------------------------------------------------------------
dataset.csv has all rows tagged train / val / test. 1.6.2 plots TRAIN ONLY.

Reason: train is what the model learns from. If a feature separates classes
in val/test but not train, that is a generalisation concern for later. For
now, look at what the model will actually see.

--------------------------------------------------------------------------------
0.6 WHY SAVE 23 INDIVIDUAL FIGURES + ONE GRID?
--------------------------------------------------------------------------------
  - Individual figure per feature: for deep reading - you zoom in and
    study one feature at a time. These go in the report appendix.
  - Grid: one figure with 23 mini-boxplots side by side - for quick scan.
    This is what you stare at first to spot dead features at a glance.

You save all of them. You CURATE which 5-10 go into the report body.
Curation happens at writing time, not here.

--------------------------------------------------------------------------------
0.7 WHAT IS THE "VERDICT PER FEATURE"?
--------------------------------------------------------------------------------
After looking at each figure, you write one word per feature:

  - INFORMATIVE : boxes at distinct heights, low overlap -> keep.
  - WEAK        : some separation, some overlap -> keep, but flag.
  - DEAD        : boxes all at the same height -> remove before Phase 2.

Dead features do not help the classifier; they just add noise and
dimensionality.

--------------------------------------------------------------------------------
0.8 WHY NO CSV OUTPUT?
--------------------------------------------------------------------------------
This step produces FIGURES and HUMAN VERDICTS, not data. Nothing downstream
reads a file from 1.6.2. 1.6.3 (correlations) reads the same dataset.csv,
not anything 1.6.2 produced.

So 1.6.2 is a DIAGNOSTIC, not a PRODUCER - same pattern as 1.6.1.

--------------------------------------------------------------------------------
0.9 WHAT LANDS IN THE REPORT?
--------------------------------------------------------------------------------
Preliminary ML §3:

  - The grid figure + 5-10 curated deep-dive figures.
  - A verdict table: feature | informative? | discriminating? | notes.
  - A sentence naming the top 5-8 features expected to carry Phase 2.
  - A sentence on any dead features.

The Excel rubric line "creativity in visualization" is satisfied here -

--------------------------------------------------------------------------------
1. ESSENCE
--------------------------------------------------------------------------------
WHAT IT IS
  A per-feature visual diagnostic. For each of the 23 feature columns in
  dataset.csv, produce a figure showing how that feature's values are
  distributed across samples, split by class.

HOW IT WORKS
  - Load dataset.csv.
  - For each feature column, plot a per-class boxplot (15 boxes, one per
    class 1..15).
  - Save each figure to disk.
  - Also produce a compact grid overview (all features in one figure).
  - Human reads the figures and writes one verdict per feature:
    informative / weak / dead.

WHY IT MATTERS
  This is the single most important EDA step for Preliminary ML §3. The
  Excel rubric explicitly rewards:
    - "Feature data visualization is appropriate"
    - "Feature quality: informative, discriminating, independent,
       explainable"
  Feature distributions are how you argue INFORMATIVE and DISCRIMINATING.
  Correlation (1.6.3) handles INDEPENDENT. EXPLAINABLE is a written
  argument.

THE CORE QUESTION
  If I look at a boxplot of feature F with 15 boxes (one per class), do
  the boxes overlap heavily (feature is weak) or sit at distinct heights
  (feature is strong)?

HOW IT DIFFERS FROM PRIOR STEPS
  1.5.2  engineered the features (produced values).
  1.5.3  assembled them into one table with labels and roles.
  1.6.1  counted class balance (how many per class).
  1.6.2  shows the SHAPE of each feature's distribution per class. First
         step that asks "does this feature actually separate classes?"

  - No CSV output feeds another script. Diagnostic, not producer.

import os
import pandas as pd
import matplotlib.pyplot as plt
import seaborn as sns

# ============================================================================
# [PARAMETERS - FILL IN BEFORE RUN]
# ============================================================================
DATASET_CSV     = r"[DATASET_CSV]"       # ...\billiards-game-clips\
                                         #    dataset.csv
OUT_DIR         = r"[OUT_DIR]"           # ...\billiards-game-clips\
                                         #    feature_dist\
FEATURE_COLUMNS = [FEATURE_COLUMNS]      # 23 column names, canonical order
ROLE_TO_PLOT    = [ROLE_TO_PLOT]         # "train" (default) or "all"
FIG_DPI         = [FIG_DPI]              # e.g. 150
GRID_COLS       = [GRID_COLS]            # e.g. 4

# ============================================================================
# LOAD
# ============================================================================
df = pd.read_csv(DATASET_CSV)
if ROLE_TO_PLOT != "all":
    df = df[df["role"] == ROLE_TO_PLOT]

os.makedirs(OUT_DIR, exist_ok=True)

# ============================================================================
# PER-FEATURE BOXPLOT, ONE FIGURE EACH
# ============================================================================
for feat in FEATURE_COLUMNS:
    fig, ax = plt.subplots(figsize=(10, 4))
    sns.boxplot(data=df, x="label", y=feat, ax=ax)
    ax.set_title(f"Distribution of '{feat}' per class ({ROLE_TO_PLOT})")
    ax.set_xlabel("Class (ball number)")
    ax.set_ylabel(feat)
    plt.tight_layout()
    plt.savefig(os.path.join(OUT_DIR, f"feature_dist_{feat}.png"),
                dpi=FIG_DPI)
    plt.close(fig)

# ============================================================================
# COMPACT GRID OVERVIEW
# ============================================================================
n = len(FEATURE_COLUMNS)
ncols = GRID_COLS
nrows = (n + ncols - 1) // ncols
fig, axes = plt.subplots(nrows, ncols, figsize=(4*ncols, 3*nrows))
axes = axes.ravel()

for ax, feat in zip(axes, FEATURE_COLUMNS):
    sns.boxplot(data=df, x="label", y=feat, ax=ax)
    ax.set_title(feat, fontsize=9)
    ax.set_xlabel("")
    ax.set_ylabel("")

for ax in axes[n:]:
    ax.axis("off")

plt.tight_layout()
plt.savefig(os.path.join(OUT_DIR, "feature_dist_GRID.png"), dpi=FIG_DPI)
plt.close(fig)

5. CODE DESCRIPTION
--------------------------------------------------------------------------------
pd.read_csv(DATASET_CSV)
  Single input. All features, labels, roles in one table.

df[df["role"] == ROLE_TO_PLOT]
  Filter to TRAIN by default. Rationale: train is what Phase 2 learns
  from; val/test are held out. If a feature separates classes on train
  but not val, that is a generalisation warning. Optionally plot "all"
  to compare, but train is the default.

sns.boxplot(data=df, x="label", y=feat)
  One box per class (1..15) side by side. Box shows median + IQR;
  whiskers 1.5*IQR; dots mark outliers. This is the most
  information-dense visual for feature-vs-class comparison at 15 classes.

    - histplot with hue=label: unreadable for 15 classes.
    - violinplot: prettier, slower to read at a glance.
    - pairplot: 23x23 pairwise, combinatorial overkill.

  Mandatory. Figures are report artefacts, not ephemeral.

plt.close(fig)
  Releases memory. 23 figures in a loop accumulate otherwise.

Grid overview
  One compact figure for quick scan / appendix. Each subplot is a
  miniature version of the individual boxplot.

8. DESIGN DECISIONS - ALL CONFIRMED
--------------------------------------------------------------------------------
(a) Idiom: per-class boxplot. One figure per feature.
    Rejected: histplot with hue (unreadable at 15 classes). Rejected:
    violinplot (slower to read at a glance). Rejected: pairplot
    (combinatorial explosion).

(b) Role filter: TRAIN only by default.
    Rejected: "all". Rationale: train is what Phase 2 learns from; the
    val/test comparison matters later, not here. Optional "all" mode
    kept for the curious.

(c) One figure per feature, plus one grid overview.
    Rationale: individual figures for deep-dive reading; grid for quick
    scan and appendix. Both serve different report needs.

(d) Save ALL 23 figures, curate for the report.
    Rationale: storage is cheap; the curation choice happens at report
    writing time, not at figure time. Do not pre-cull.

(e) No machine-consumed CSV output.
    Rationale: same as 1.6.1. The consumers are the human decision and
    the report. No downstream script reads this.

(f) No automatic feature-ranking.
    Rationale: automated separability metrics (e.g., ANOVA F-score) are
    a 1.7/Phase-2 concern. 1.6.2 is visual. The human reads the boxes
    and writes verdicts.

--------------------------------------------------------------------------------
9. RESCALE / FALLBACK TRIGGERS
--------------------------------------------------------------------------------
- If a feature's boxplots are flat lines at a single value across all
  classes (feature is constant):
    -> mark as DEAD; flag for removal at Phase 2 feature selection.
- If ALL 23 features show heavy overlap across all 15 classes:
    -> the feature engineering at 1.5.2 has failed. Revisit mask
       extraction (1.5.1 thresholds) and hole detection (1.5.2 hole
       algorithm). This is a blocking finding, not a report limitation.
- If a specific class (e.g. class 3) shows noisy boxes:
    -> cross-check with 1.6.1. If class is thin (< 30 in train),
       the noise is expected. Note in report.
- If striped classes (9-15) separate from solid (1-8) on a feature,
  but not from each other:
    -> feature is a solid/stripe discriminator, not a digit
       discriminator. Note this; it is useful for the 6/9 tie-breaker
       but not for primary classification.
