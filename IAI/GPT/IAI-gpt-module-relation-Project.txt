PROJECT - IAI SUBCOMPONENT UNDERSTANDING AND ROADMAP

================================================================================
1. UNDERSTANDING THE PROJECT
================================================================================

Project: Solo S7 minor project - Embedded Vision System with AI for Billiards &
Snooker.

Goal: Overhead camera + embedded SBC detects game start, increments a game
counter, optionally calculates bill, emits software trigger. No coins, timers,
staff, cloud.

Scope: Billiards & snooker, autonomous game counting, optional billing.

Requirements: FR1-FR7 (detect new game, count, bill, distinguish ball types,
apply rules, output, no user input). TR1-TR9 (embedded, camera, full vision
chain, real-time, standalone, scalable, no cloud, rule sets, NDA).

NDA: Source/design restricted. Only functional exhibition for assessors without
NDA.

Your subcomponent: OCR of numbers on billiard balls. Snooker balls have no
characters. So this applies only to billiards/pool balls (1-15) and cue ball
(no number). It supports ball identification and rule logic.

================================================================================
2. HOW IAI RELATES TO THE PROJECT SUBCOMPONENT
================================================================================

IAI (EVML-EVD3) teaches ML/DL for computer vision.

Your project subcomponent - OCR of numbers on billiard balls - is a
digit/character classification problem on ball surfaces.

It fits IAI's project option 3: ML objective in your EVML project (replace the
classifier in step 5 of the conventional vision train).

So your IAI assessments should be scoped only to the OCR subcomponent, not the
whole billiards system.

Relevant IAI lessons: feature extraction, EDA, supervised ML, performance,
ANN/CNN, transfer learning, edge deployment.

================================================================================
4. WHAT IAI ASSESSMENTS NEED FROM THE PROJECT SUBCOMPONENT
================================================================================

All IAI reports must follow templates and acceptance criteria. Scope = OCR
subcomponent only.

Preliminary ML Report
---------------------
- Sections 1-3: Introduction, Problem Statement, Data Acquisition & Exploration.
- Problem statement: SMART objective for OCR of billiard ball numbers.  Functional + technical requirements prioritised.
- Data acquisition: Images of numbered balls, various angles, lighting,  distances. Label ball numbers. Assess data quality (representative,  sufficient, balanced, unbiased).
- Feature engineering: Hand-crafted features (colour, shape, Hu moments, ORB).
- EDA: Histograms, scatter, box, correlation. Feature quality (informative,  discriminating, independent, explainable).
- Preprocessing: Cleaning, scaling, pipeline.
- Peer review: Excel feedback from/to another team.

Full ML Report
--------------
- Sections 1-9: Include preliminary + feedback + model selection, training,  validation, deploy/test, conclusion.
- Model selection: Compare SVM, k-NN, RF, etc. Argue best for OCR.
- Training: Cross-validation, grid search, overfitting prevention.
- Testing: Confusion matrix, precision/recall/F1 per digit/number.
- Deploy: Pipeline on SBC or training machine. Test plan against SMART  requirements.
- Conclusion: Compare results to goals, generalisation, limitations.

DL Report
---------
- Sections 1-7: Introduction, Problem statement (updated), Data augmentation &  preprocessing, CNN architecture & training, Deploy & test, Conclusion,  References.
- Both required: Custom CNN AND transfer learning model for OCR.
- Augmentation: Rotation, blur, perspective, lighting, etc.
- Training: Hyperparameter tuning, overfitting prevention.
- Comparison: Custom CNN vs transfer learning vs ML approach.
- Deploy: TFLite/edge, test plan, results.
- Visualisation: Feature maps, Grad-CAM, at least 2 layers.

Quizzes: 20% of each period. Study all IAI lessons.

================================================================================
6. BREAKDOWN OF EACH PHASE
================================================================================

Phase 0 - Setup & Scope
-----------------------
0.1 Install Python 3.11, venv, pip install -r requirements.txt.
0.2 Set EVML_DATA, verify OpenCV/sklearn/TF.
0.3 Git repo, IDE, Colab if needed.
0.4 Define OCR subcomponent: classify ball numbers 1-15 + cue ball. Snooker excluded.
0.5 Form team (if IAI requires 2-3; solo still possible but check).

Phase 1 - Data Acquisition & Feature Engineering
------------------------------------------------
1.1 Build controlled capture setup: overhead camera, stable lighting, fixed distance.
1.2 Capture images of billiard balls with visible numbers. Vary angle, distance, lighting, background.
1.3 Label each ball crop with number (1-15) or cue.
1.4 Split data: train/validation/test, stratified.
1.5 Extract classical features: colour histograms, Hu moments, contour, ORB.
1.6 EDA: class balance, feature distributions, correlations.
1.7 Preprocessing: cleaning, scaling, pipeline.
1.8 Deliverable: Preliminary ML report Sections 1-3 (wk 40).

Phase 2 - Classical ML Model & Preliminary Report
-------------------------------------------------
2.1 Train SVM, k-NN, random forest on features.
2.2 Cross-validate, grid search hyperparameters.
2.3 Evaluate: confusion matrix, precision/recall/F1 per digit.
2.4 Write preliminary report, submit wk 40.
2.5 Peer review another team (wk 41).
2.6 Incorporate feedback.

Phase 3 - Full ML Model & Report
--------------------------------
3.1 Finalise best classical model.
3.2 Deploy pipeline (Flask/Docker/edge) on SBC or training machine.
3.3 Test against SMART requirements (accuracy, speed, lighting, distance).
3.4 Write full ML report Sections 1-9 (wk 45).
3.5 Include feedback sheets from/to another team.

Phase 4 - Custom CNN & Transfer Learning
----------------------------------------
4.1 Build custom CNN for OCR on ball crops.
4.2 Augment data: rotation, blur, perspective, lighting, noise.
4.3 Train, validate, tune (Keras Tuner / GridSearchCV).
4.4 Transfer learning: MobileNet, ResNet, ViT. Freeze layers, fine-tune.
4.5 Compare custom CNN vs transfer learning.

Phase 5 - DL Deployment & Comparison
------------------------------------
5.1 Convert to TFLite, quantize, prune if needed.
5.2 Deploy on SBC. Benchmark inference speed, accuracy.
5.3 Test plan: accuracy, FPS, lighting, distance.
5.4 Compare DL vs ML approach.

Phase 6 - Final DL Report & Integration
---------------------------------------
6.1 Write DL report Sections 1-7 (wk 2.9).
6.2 Include custom CNN + transfer learning, augmentation, training, deployment, comparison with ML.
6.3 Visualise layers (feature maps, Grad-CAM).
6.4 Integrate OCR subcomponent into project's rule logic (optional, if time).
6.5 Submit DL report.
