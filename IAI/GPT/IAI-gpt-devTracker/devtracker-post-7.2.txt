PART D - CNN RECOVERY MECHANISM (THOROUGH)
================================================================================

WHAT A CNN IS, LAYER BY LAYER

  Layer                       Operation                    What it learns
  --------------------------  ---------------------------  ---------------------
  Conv2D                      Sliding kernel, mult+sum     detects local
                                                           patterns; weights
                                                           LEARNED, not fixed
  ReLU                        max(0, x)                    non-linearity
  MaxPool                     take max in each window      downsample; small
                                                           translation tolerance
  Conv -> Pool x N            repeated                     hierarchy: edges ->
                                                           strokes -> parts ->
                                                           numerals
  Flatten/GlobalAvgPool       collapse spatial             1D vector per image
  Dense                       fully connected              classify
  Softmax                     normalize to [0,1]           class probabilities

THE KEY DIFFERENCE FROM HAND-FEATURES

Hand-features are FIXED MEASUREMENTS: "count holes," "binned projection
mass." A CNN's features are LEARNED WEIGHTS. Nobody told it that "loop
position" matters - it discovered that by minimizing loss on the training
data.

WHY CNN RECOVERS EACH FAILURE

Failure 1 - 5 dead hole features
  Classical: find_holes() requires a solid white patch with enclosed dark
             regions. Resolution kills the patch. Features return 0. Dead.
  CNN:       First conv layer sees raw pixel values. It does not care
             whether the patch is solid, fragmented, or half-covered by
             stripe. Whatever LOCAL PATTERN correlates with class 8 vs 3
             gets weight. No precondition of "disk with holes."
  Mechanical: 3x3 kernel sliding over a 40x40 crop with a faint "8" outline
              produces activations at the STROKES of the 8 - regardless of
              whether the patch "looks like" a disk.

Failure 2 - proj_x / proj_y rotation-invariance
  Classical: Features designed identical under 180-degree rotation. Good
             for generalization, catastrophic for 6 vs 9. Both produce the
             same projection profile.
  CNN:       Not inherently rotation-invariant. A conv kernel that fires on
             "loop at top" fires ONLY when loop is at top. Feed a 6 and a 9
             without rotation augmentation - the network has access to the
             distinguishing signal.
  CORE INSIGHT: hand-features THREW AWAY exactly the information needed to
                solve 6/9. The CNN does not throw it away by default.

Failure 3 - resolution ceiling (30-50px crops)
  Classical: Mask threshold collapses 1-2px strokes into nothing.
             MIN_MASK_AREA=30 rejects most. What survives loses numeral
             shape.
  CNN:       Works on grayscale values, not binary masks. An 8 with 1px
             strokes still produces a structured pixel pattern. Conv kernels
             can fire on it. Not perfect - but the failure mode is
             DEGRADATION, not TOTAL LOSS.
  Compare:
    Classical: stroke lost -> mask empty -> 0 features -> unclassifiable.
    CNN:       stroke present as 1px line -> low activation but non-zero
               -> classifiable with more examples.

Failure 4 - feature overlap (4/9, 11/1, 2/5)
  Classical: Measured only TWO silhouette axes. If classes overlap on both,
             indistinguishable regardless of algorithm.
  CNN:       Learns a HIERARCHY. L1 finds edges. L2 combines into corners.
             L3 combines into curve fragments. L4 combines into "top-left of
             a 4 or top-left of a 9." Overlap in 23-dim hand space !=
             overlap in network's learned 64- or 128-dim space.
  Concretely: the INTERNAL of the numeral - hollow regions, stroke
              thickness, curvature at each corner - was never captured by
              silhouette projection. CNN sees it.

WHAT CNN CANNOT DO

  Limit                 Why
  --------------------  ------------------------------------------------
  492 crops             small; overfitting risk; transfer learning
                        mitigates
  30-50px crops         far below 224x224 a pretrained model expects;
                        upsampling helps, not fixes
  6/9 without care      augmentation must NOT blanket-rotate
                        (brightness/contrast/perspective only)
  Interpretability      black box; Grad-CAM helps but does not match the
                        Hu-moment story
  Certainty of recovery expected, not guaranteed; realistic 6-8 classes
                        >=70%

THE MECHANISM IN ONE SENTENCE

Hand-features were a HYPOTHESIS about what matters (holes + projections).
The hypothesis was wrong for this data (holes dead, projections
rotation-invariant). CNN replaces the hypothesis with LEARNED WEIGHTS - it
discovers which measurements matter, from the pixels themselves.

PART E - WHY MASKING, IF CNN DOES NOT NEED IT
================================================================================

SHORT ANSWER: two parallel pipelines for two different deliverables.

  Pipeline              Consumer            Deliverable
  --------------------  ------------------  ------------------------------
  Phase 1-3 (data ->    SVM / k-NN / RF     Prelim ML report +
  features -> class ML)                     Full ML report
  Phase 4 (raw crops    CNN                 DL report
  -> CNN)

The Prelim ML report is due at end of Phase 1. Phase 4 has not started.
Masking was the ONLY feature path available at that point.

WHAT THE TEMPLATE ACTUALLY REQUIRES

From {GROUP}_preliminary_ML_report.docx Sec 3 "Data acquisition and
exploration":
  - Make an image set
  - Label each photo
  - Make visual representations
  - Assess data quality (representative, sufficient, balanced, unbiased)

From peer review rubric (Batch 6):
  - "Data collected, FEATURES ENGINEERED AND ARGUED"
  - "Feature data visualized and explored"
  - "PREPROCESSING PIPELINE DISCUSSED AND IMPLEMENTED"

The template does NOT say "use masking." It says "engineer features."
Masking is the CHOSEN METHOD for producing numeral-geometry features.

WHY MASKING SPECIFICALLY - FOR PHASE 2

  Alternative                   Why rejected (devtracker 1.5.1)
  ----------------------------  ----------------------------------------
  Raw pixels as features        3,600 dims on 505 samples -> curse of
                                dimensionality
  Colour histograms             billiard balls share colours across
                                classes (8 and 9 both dark)
  Hu moments on full ball       rotation-invariant -> 6/9 collapse
  ORB keypoints                 poor on small low-contrast numerals
  Mask + hole + projection      ONLY option offering interpretable,
                                rotation-relevant numeral geometry

Masking was not mandated. It was the BEST AVAILABLE CHOICE given the
classical-ML constraint. The partial failure (5 dead features) is itself
a FINDING - arguably valuable, because it demonstrates depth of analysis.

DOES THE PRELIM ML REPORT PENALIZE THE MASKING CHOICE?

No. Rubric rewards:
  - Creativity in feature engineering - masking is creative
  - Argumentation - argued in writing
  - Quality discussion - the 5-dead finding is exactly the "depth of
    analysis" the rubric asks for
  - Critical reflection - documented limitation meets this criterion

The report does not ask "did your features work perfectly?" It asks "did
you engineer, argue, analyse, and reflect?" The pipeline does all four.

WHY THE COMPARISON MATTERS

DL report template (Batch 6, Sec 4) REQUIRES:
  - Custom CNN
  - Transfer learning model
  - COMPARISON WITH ML APPROACH

That comparison is only meaningful if the ML approach was actually BUILT
and EVALUATED. The masking path IS the ML approach. Without it, there is
nothing to compare CNN AGAINST. The 5-dead finding is what makes the
comparison narratively strong - "classical plateaued at X due to feature
limitations; CNN reached Y by learning directly."

SO MASKING IS NOT WASTED EFFORT. IT IS:
  1. Required by the Prelim ML report (features engineered)
  2. The classical-ML path Phase 4 must be compared against
  3. A DOCUMENTED CEILING that justifies Phase 4's existence
  4. Itself a finding - the failure is informative

CNN bypassing masking is not an argument that masking was wrong. It is the
argument that a DIFFERENT APPROACH WAS NEEDED - which is exactly what the
DL report is set up to demonstrate.
