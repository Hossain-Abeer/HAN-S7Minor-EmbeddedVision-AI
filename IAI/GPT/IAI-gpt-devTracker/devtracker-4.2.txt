================================================================================

PURPOSE
-------
Assign semantic labels (class 1-15) to the 1,438 geometric crops produced by
3.3. Delete unusable crops (no visible numeral, merged blobs, false positives)
to finalize the dataset before the 4.4 audit and 5.1 split.

PREREQ
------
3.3 (Full extraction run: 1,438 crops in unsorted_png/), 
4.1 (Class folders 1/ ... 15/ confirmed to exist).


================================================================================
1. ESSENCE & ROLE IN THE CHAIN
================================================================================
1.3.1 through 1.3.2 produced GEOMETRY (bounding boxes).
4.2 produces SEMANTICS (the actual class label).

Role: LABEL ASSIGNMENT & QUALITY GATE. 
This is the step where the dataset becomes machine-readable by Scikit-Learn
and Keras. Because the numerals on the balls are pre-existing, this is a 
SORTING task, not a human-annotation-from-scratch task. 

The 64% deletion rate is not an error; it is the system working as designed.
The motion gate in 3.3 over-produces candidates (cue balls, HUD elements, 
occluded balls) to ensure recall. 4.2 is the precision filter.


================================================================================
2. TOOLING DECISION & ENVIRONMENT RECOVERY (CRITICAL)
================================================================================

ATTEMPTED HYBRID APPROACH (FAILED)
The plan was an OCR-assisted pre-sort using `CnOCR` (to auto-label high-
confidence digits) followed by manual review for leftovers.

TOOLING FAILURE
Installing `cnocr` caused a cascade failure:
  1. Its resolver upgraded `numpy` to 2.4.6, breaking the ABI for 
     TensorFlow 2.15.1, torch 2.2.2, and cv2 4.11.0.
  2. It installed `opencv-python-headless` 5.0.0, which hollowed out the 
     existing `cv2` module.
  3. It installed an incompatible `rapidocr` version, causing an ImportError 
     inside CnOCR.

RECOVERY ACTIONS
  - Uninstalled CnOCR and all orphaned dependencies (rapidocr, wandb, 
    ultralytics, shapely, opentelemetry, etc.).
  - Re-pinned numpy (<2.0), pandas (<2.2).
  - Reinstalled opencv-python (4.11.0.86).
  - Verified env: `pip check` = "No broken requirements found." Core imports 
    (tf, torch, cv2, sklearn) verified clean.

FINAL DECISION: CUSTOM KEYBOARD GUI
Abandoned OCR. The dependency fragility of external ML-OCR libraries posed 
too high a risk to the pinned TF/PyTorch environment. 
Built `src/keyboard_sorter.py` (Tkinter GUI, zero external ML dependencies). 
This guarantees environment stability while achieving the same goal.


================================================================================
3. MECHANICS - KEYBOARD SORTER GUI
================================================================================
Tool: `src/keyboard_sorter.py`

WHY CUSTOM GUI OVER EXPLORER?
  - Speed: Keyboard-only sorting is ~5x faster than drag-and-drop.
  - Context: Displays full filename and running tally.
  - Safety: Binds keys explicitly; accidental deletions require hitting 'x'.

KEY MAP
  1-9       -> Move to class 1-9
  q, w, e   -> Move to class 10, 11, 12
  a, s, d   -> Move to class 13, 14, 15
  x         -> DELETE (junk/illegible)
  space     -> SKIP (leave in root for later)
  ESC       -> Quit

BEHAVIOR
  - `shutil.move()` is used to preserve filenames and metadata.
  - If a crop cannot be read (corrupt PNG), it is skipped automatically.
  - Counter updates dynamically `[current/total]`. 
  - No data is modified, only relocated.

================================================================================
5. DEVIATION, IMBALANCE, & MITIGATION
================================================================================

THRESHOLD FAILURE
The 1.3.5 audit floor is 50 crops/class. Only Class 1 (83) passes. 
Classes 10 (12) is severely short. 13 other classes sit at 24-45.

WHY DID THIS HAPPEN?
  - The motion gate captures ~25 settle-events per clip.
  - Some balls are rarely visible (e.g., Class 10 is pink; easily obscured).
  - Class 1 (yellow) might have been clustered near the camera or left 
    until the end of the games.

ESCALATION ANALYSIS
Standard devtracker trigger: re-run 3.3 with `FRAME_STRIDE = 3`.
WHY IT WON'T WORK: `FRAME_STRIDE` is ALREADY 1. The bottleneck is the 
number of unique shots (settle events), not the frame sampling rate.
Re-recording clips is out of scope.

DECISION: PROCEED
Per the IAI module's grading criteria (instructor Jeroen Veen prioritizes 
a functional end-to-end pipeline over large datasets), we proceed with 513 
crops. 

DOWNSTREAM CONSEQUENCES
  - 1.6.1 (EDA): Will detect a ~7:1 imbalance. Will likely trigger 
    `class_weight='balanced'` for Phase 2 (SVM/RF).
  - Phase 4 (CNN): Requires aggressive augmentation to prevent overfitting 
    on minority classes (Class 10, 2, 7, 13).
  - Reports: This limitation MUST be explicitly stated in Preliminary ML §3 
    and DL Report §6.
