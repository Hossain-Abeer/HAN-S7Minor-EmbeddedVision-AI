================================================================================
PART A - THE DEBUGGING JOURNEY (TUNING PARAMETERS)
================================================================================

The dry run was executed multiple times, requiring three distinct parameter 
fixes in `config.py` to accommodate the Clipchamp-exported video.

ISSUE 1: BLUR FILTER REJECTED EVERYTHING
  - Result: kept=0, crops=0.
  - Diagnosis: The Laplacian Variance (sharpness) of the first frame was 97.73. 
    The default `BLUR_THRESHOLD` was 100.0. Clipchamp's re-encoding slightly 
    softened the pixels, falling below the threshold.
  - Fix: Changed `BLUR_THRESHOLD = 50.0` in config.py. (Still high enough to 
    reject genuine blur, but accepts the Clipchamp export).

ISSUE 2: DUPLICATE FILTER REJECTED STATIC SCENES
  - Result: kept=1, crops=0.
  - Diagnosis: The log showed metric_value hovering around 3.3. The 
    `DUP_THRESHOLD` was 5.0. The video started with a completely static scene 
    (before the break), so the pixel difference was too low.
  - Fix: Retrimmed the video in Clipchamp to start *after* the break (balls 
    moving). Lowered `DUP_THRESHOLD = 3.0` in config.py to catch slow-moving 
    balls while still rejecting true duplicates.

ISSUE 3: NO BALLS DETECTED
  - Result: kept=1, crops=0. (The surviving frame yielded nothing).
  - Diagnosis: As detailed in 3.1 Part B, `RETR_EXTERNAL` caused OpenCV to 
    ignore the balls. 
  - Fix: Changed to `RETR_LIST` in the Python code. 
  - Follow-up: Once contours were found, the balls had an Area of ~1796. The 
    config had `MIN_BALL_AREA = 2000`. 
  - Fix: Updated `MIN_BALL_AREA = 800` and `MAX_BALL_AREA = 6000` in config.py.
