[4] FIRST ACTIVATION ATTEMPT - FAILED SILENTLY
    Command:  C:\dev\envs\IAI-env\Scripts\activate
    Result:   No error, no prompt change, no activation.
    Cause:    Two problems compounded:

[5] MISLEADING VERIFICATION - python --version showed 3.11.9
    Command:  python --version
    Result:   Python 3.11.9
    Misleading because: version matched the venv's base (both are 3.11.9),
              giving false impression that activation succeeded.
    Diagnosis: `Get-Command python` revealed:
                 Source = C:\dev\python311\python.exe
               i.e. the GLOBAL Python, not the venv.
    Confirms: Version equality alone is NOT proof of activation.
              Must check path, not version.

[6] SECOND DIAGNOSTIC - where python returned nothing
    Command:  where python
    Result:   Empty output.
    Cause:    In PowerShell, `where` is an alias for `Where-Object`, a
              cmdlet for filtering collections. It does not search PATH.
    Fix:      Use `where.exe` (explicit binary) or `Get-Command python`.

[7] CONFIRMED VENV INACTIVE
    Command:  $env:VIRTUAL_ENV
    Result:   Empty (no value).
    Meaning:  The activate script sets $env:VIRTUAL_ENV as its primary

KEY LESSONS / GOTCHAS
---------------------

1. PowerShell activation requires the .ps1 variant:
   - WRONG:  ...\Scripts\activate
   - RIGHT:  ...\Scripts\Activate.ps1

2. Version output is not proof of activation:
   - Same-version venvs are indistinguishable by version alone.
   - Always verify with $env:VIRTUAL_ENV or where.exe python.

3. `where` in PowerShell is not the PATH search tool:
   - Use `where.exe` or `Get-Command`.

4. `python -m venv` creates the folder; mkdir is redundant.

5. ExecutionPolicy RemoteSigned (default on many Windows setups) is
   sufficient. No admin needed if Scope = CurrentUser.

6. Base Python without pip is fine:
   - venv bootstraps pip into the venv's own Scripts\ folder.

7. Activation is per-shell-session:
   - Open a new terminal -> venv is not active -> must re-run Activate.ps1.

[1] CLARIFIED MODEL: requirements.txt vs venv path
    Question from user: "If requirements.txt lives in D:\..., why does pip
    install into C:\dev\envs\IAI-env\?"
    Answer:
      - requirements.txt is INPUT (a list).
      - site-packages is OUTPUT (install destination).
      - pip installs to the ACTIVE interpreter's site-packages,
        regardless of CWD.
      - `-r requirements.txt` is a RELATIVE path resolved against CWD.
      - So: cd to the file's folder, then run pip. The install still
        goes to the venv.

[2] CLARIFIED PROMPT ANATOMY
    Prompt format:
        (IAI-env) PS D:\HAN\...\IAI>
         \_____/ \/ \___________/
          venv    shell   CWD
    - Venv label = cosmetic.
    - Shell      = interpreter of commands.
    - CWD        = where relative paths resolve.
    - Install target = determined by which pip.exe runs (PATH), not CWD.

KEY LESSONS / GOTCHAS
---------------------

1. requirements.txt is input, site-packages is output. CWD only matters
   for locating the file, not for install destination.

2. Use `python -m pip` for upgrades inside venvs — guarantees the right
   pip.

3. pip resolver "looking at multiple versions" is normal, not a failure.
   It is backtracking to satisfy upper bounds.

4. Upper-bound pins force intentional downgrades:
   - opencv-python 5.x -> 4.11 (numpy 1.x compatibility)
   - tf-keras 2.21  -> 2.15 (tensorflow 2.15 compatibility)

5. CPU-only torch (`+cpu` suffix) is expected without CUDA installation.
   Use Google Colab for GPU workloads.

6. Total install ~700 MB. Cleanup tip:
   - pip cache (C:\Users\<user>\AppData\Local\pip\cache\) can be purged
     after successful install to reclaim ~500 MB.

7. To silence TensorFlow warnings permanently:
     [Environment]::SetEnvironmentVariable(
       "TF_CPP_MIN_LOG_LEVEL", "3", "User")
     [Environment]::SetEnvironmentVariable(
       "TF_ENABLE_ONEDNN_OPTS", "0", "User")

8. Backtracking takes time. For slow connections, consider:
   - `pip install --prefer-binary -r requirements.txt`
   - or a mirror (`-i https://pypi.org/simple/` default; alternatives
     exist for regional speedups).

9. Activate before every session:
   - `C:\dev\envs\IAI-env\Scripts\Activate.ps1`
   - Otherwise pip/python resolve to global and installs leak.
