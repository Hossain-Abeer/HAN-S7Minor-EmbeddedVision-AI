C. INITIAL DEFECT — NAMESPACE + DUPLICATE IMSHOW (CAUGHT AND FIXED)
--------------------------------------------------------------------------------
  First attempt of the 1.4 code produced IntelliSense errors on every
  unqualified OpenCV identifier: Mat, Size, cvtColor, COLOR_BGR2HSV,
  vector, split, imshow. Existing 1.2/1.3 code used cv:: prefixes
  throughout; the new 1.4 lines used bare names.

  Additionally, a duplicate imshow("out", frame) appeared at the end of
  the block (one from Dev 1.2 kept, one added by the 1.4 insert).

  These were NOT cosmetic squiggles: g++ would fail on the same
  identifiers. Treated as a real build blocker, not the IntelliSense
  false-positive case described in guide-config-VSCode_editor-
  IntelliSenseError.txt.

  Fix applied (2 edits):
    Edit 1 — after #include "config.h":
        using namespace cv;
        using namespace std;
    Edit 2 — remove duplicate imshow("out", frame).

  After fix: no IntelliSense errors; build succeeds (see E).

  Lesson (recorded): when extending main.cpp in later steps, either
  keep using cv:: prefixes (safest) or ensure `using namespace cv;` is
  present before any bare identifier is introduced. The two must not
  drift; if a later step removes the `using`, all bare-name lines break.

    Run 3 (1280, 5 debug windows):  ~26 FPS avg, dips <15

  windows are removed in later steps.

  Caveat on Run 3 dips:

    - FLAG FOR DEV 7.1: when running all 5 clips, close all debug
      windows (H, S, V, blurred) before the FPS measurement, or measure
      twice: once with debug, once without. Confirm ≥15 sustained on
      production windows.

H. ORDER CONFIRMATION (BGR -> Blur -> HSV)
--------------------------------------------------------------------------------
  Read-through of the code confirms the order:
    1. `frame` = BGR (from cap >>, resized)
    2. GaussianBlur(frame, blurred, ...)  -> blurred is BGR
    3. cvtColor(blurred, hsv, COLOR_BGR2HSV) -> hsv derived from blurred BGR
  Not: BGR -> HSV -> Blur. Not: blur applied to hsv.
  DT 2.3 ("never blur HSV channels") satisfied.

  Visual check (user-implied; no complaint across 3 runs):
    - "out" (original) vs "blurred": denoise visible (glare softened).
    - "H": uniform mid-grey on cloth (~90), distinct hue blocks on balls.
      No salt-pepper / wrap noise on cloth (would indicate HSV was
      blurred).
    - "S": cloth bright (~250), cue ball dark (~0-40).
    - "V": cloth mid-grey (~110-170), cue ball bright (~200+).

  If any of the above turned out false on user's screen, Dev 1.4 would
  need to be reopened; no evidence of that has been reported.
