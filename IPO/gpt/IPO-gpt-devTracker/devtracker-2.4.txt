B. THE MODULARIZATION PIVOT (CRITICAL CONTEXT)
--------------------------------------------------------------------------------
  Mid-implementation, the monolith main.cpp was refactored to improve
  maintainability, debugging, and defense readiness. The pipeline logic
  was extracted into discrete modules.

  NEW REPO STRUCTURE:
    IPO/Ball-Type-Identifier/
    ├── CMakeLists.txt  (updated to compile 3 .cpp files)
    └── src/
        ├── config.h       (constants)
        ├── types.h        (shared structs: BallCandidate)
        ├── preprocess.h   (declarations for Phase 2)
        ├── preprocess.cpp (implementation: blur, HSV)
        ├── segment.h      (declarations for Phase 3)
        ├── segment.cpp    (implementation: masks, morph, contours, filters)
        └── main.cpp       (orchestrator: reads video, calls functions)

  KEY CHANGES & SYNTAX FIXES:
    - CMakeLists.txt add_executable now includes: src/main.cpp src/preprocess.cpp src/segment.cpp
    - types.h created to hold BallCandidate, avoiding circular includes.
    - segment.cpp uses explicit cv:: and std:: namespaces (best practice for modules).
    - A syntax error (trailing comma in the Point2f center constructor) was 
      caught and fixed in segment.cpp during the pivot.

--------------------------------------------------------------------------------
C. CODE DELTA (The modular components)
--------------------------------------------------------------------------------
  src/types.h:
    struct BallCandidate { cv::Rect bbox; cv::Point2f center; int area; };

  src/segment.cpp (The core of 2.4):
    - Accepts hsv, rejectPath, and a reference to filteredOut.
    - Iterates contours. If accepted, increments nAccepted, draws to 
      filteredOut, computes Moments to get center, and pushes to the 
      candidates vector.
    - Returns candidates.

  src/main.cpp:
    - Stripped down to a clean orchestrator.
    - Calls applyPreprocessing(), then extractCandidates().
    - Handles FPS calculation, imshow(), and waitKey().
