  already exists at:

      D:/HAN/Semester 7 Minor/HAN-S7Minor-EmbeddedVision-AI/.vscode/
      settings.json

  Its pre-existing content was:

      {
          "cmake.sourceDirectory": "D:/HAN/Semester 7 Minor/
                                   HAN-S7Minor-EmbeddedVision-AI/IPO/Ex2_1",
          "cmake.buildDirectory": "${sourceDir}/build",
          "cmake.options.statusBarVisibility": "visible"
      }

  Two decisions were considered:

    OPTION A — create a second .vscode/settings.json inside
               IPO/Ball-Type-Identifier/.

    OPTION B — reuse the workspace-level file, editing only the
               cmake.sourceDirectory line.

  DECISION: Option B.

  Rationale:
    - One settings file = one source of truth. Duplicating creates drift
      risk (which one wins if they conflict?).
    - The workspace-level file already has cmake.buildDirectory set to
      ${sourceDir}/build, which correctly produces build/ under whichever
      source dir cmake.sourceDirectory points to. No need to redeclare.
    - The project's own guide (guide-config-path_per_exercise-build.txt)
      prescribes exactly this pattern: "Update ONLY this line per
      exercise: cmake.sourceDirectory".
    - The pre-existing file used an absolute path
      (D:/HAN/.../IPO/Ex2_1). The guide specifies using ${workspaceFolder}
      instead, for portability. That was corrected in the same edit.

  The single-line edit applied:

      "cmake.sourceDirectory":
          "${workspaceFolder}/IPO/Ball-Type-Identifier",  // change per exercise

  All other lines preserved verbatim:
      "cmake.buildDirectory": "${sourceDir}/build",
      "cmake.options.statusBarVisibility": "visible"

  Consequence: no .vscode/ folder is created inside
  IPO/Ball-Type-Identifier/. Dev 0.1 D2 ("`.vscode/` absent at this point,
  expected") remains valid: the absence is permanent, not pending.
