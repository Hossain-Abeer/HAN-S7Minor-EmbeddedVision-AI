C. DOCUMENTED LIMITATION: GREEN-ON-GREEN CAMOUFLAGE
--------------------------------------------------------------------------------
  Observation: The solid green ball (6-ball) is only detected when rolling. 
  When stationary, it is masked out by the cloth HSV range.

  Root Cause (Pixel Count & Motion): 
  - When stationary, the ball's HSV perfectly overlaps the cloth. The visible 
    contour shrinks until it falls below MIN_BALL_AREA (200 pixels), triggering 
    rejection.
  - When rolling, motion blur and specular shifts alter the pixel values. The 
    contour expands above the 200-pixel threshold, passing the area filter.
  - Similarly, the stripe ball's bounding box glitches during rolling due to 
    motion blur stretching the contour (affecting aspect ratio and edge density), 
    but stabilizes when still.

  Decision: This is an ACCEPTED LIMIT. Color-space segmentation without depth 
  or IR cannot perfectly isolate identical hues. This will be documented in 
  docs/robustness.md under F2 (Overlap/Camouflage) for the defense.

D. CODE EXPLANATION
--------------------------------------------------------------------------------
  1. The Rule Order (classify.cpp):
     - `if (wr > RATIO_CUE)`: Highest priority. White ball dominates.
     - `else if (wr > UNCERTAIN_WHITE_HI)`: Extreme glare between 0.60 and 0.65.
     - `else if (wr >= RATIO_STRIPE_LO)`: Stripe range (0.15 to 0.60).
     - `else if (wr >= SOLID_WHITE_LO && ed > EDGE_SOLID_MIN)`: Solid with a 
       visible numeral ring (high edge density).
     - `else`: Catch-all for dark solids (wr < 0.15, ed < 0.10). This prevents 
       the 8-ball and 7-ball from falling into UNCERTAIN.

  2. Color Mapping (main.cpp):
     - CUE    -> White box  (Scalar 255,255,255)
     - SOLID  -> Red box    (Scalar 0,0,255)
     - STRIPE -> Cyan box   (Scalar 255,255,0)
     - UNCERTAIN -> Yellow box (Scalar 0,255,255) with label "?"
