F. CAVEATS / OBSERVATIONS RECORDED (non-blocking)
--------------------------------------------------------------------------------
  D1. ftyp check is necessary but not sufficient.
      Container-level validity does not guarantee the H.264 stream
      decodes cleanly on this workstation's OpenCV build. Codec/decoder
      availability is proven at Dev 1.2 (cap.isOpened() on clip1) and
      Dev 7.1 (all 5 clips). If Dev 1.2 fails on clip1 despite ftyp
      being present, the likely cause is a codec pack mismatch, not a
      corrupt file. Handle at that step, not here.

  D2. File sizes are matched to DT 0.3 B exactly, not approximately.
      Any future drift (e.g. an accidental editor open + save) would
      change the byte count and would surface at the next Dev 0.4-style
      check. This is intentional: any change to a clip is treated as a
      signal to stop and re-establish provenance.

  D3. Working-directory jump.

      to the repo. Subsequent steps (Dev 1.1, 1.2) must return to the
      repo root before running CMake or g++. Recorded so Dev 1.1 does
      not accidentally invoke CMake from game1/.

      0.3 D4).
      Still 3 commits ahead. Dev 0.4 produces no commit. Flush at the
