--------------------------------------------------------------------------------
D. PITFALLS RECORDED
--------------------------------------------------------------------------------
  D1. Self-scanning grep scripts.
      A script that lives inside the tree it scans will match its own
      forbidden-token list. Fix: restrict -Include to source extensions,
      OR place the script outside the scanned root. Chosen: -Include.

  D2. Forbidden-token "OCR" appears in prose comments.
      The word "OCR" is legitimate English when explaining what is NOT
      implemented. But the grep cannot distinguish prose from code.
      Fix: reword comments to avoid literal forbidden tokens; preserve
      meaning ("text-recognition" instead of "OCR"). This is a
      deliberate lexical discipline, not a semantic change.

  D3. Header guard ordering bug (carried to 0.5).
      src/config.h currently has:
          constexpr const char* DATA_ROOT = "...";   <-- before guard
          #pragma once                                <-- AFTER DATA_ROOT
      Effect: if config.h is included twice in different TUs, DATA_ROOT
      is a constexpr so no ODR violation, but if the enum BallType is
      also pulled in, duplicate definition across TUs depends on
      #pragma once already having been processed. In practice MinGW
      tolerates this because #pragma once is seen on first include, but
      it is incorrect style and must be fixed.
      Required fix in 0.5: move #pragma once to line 1, before DATA_ROOT.

  D4. scripts/ folder omitted.
      Initial design assumed scripts/ at repo root. Not created; the
      .ps1 lives in src/. DesignTracker 0.2 layout does not mention a
      scripts/ folder, so this is consistent, but 0.4 log notes it so
      future grep scripts are placed with the same -Include discipline.
