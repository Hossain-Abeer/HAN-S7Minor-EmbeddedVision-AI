D. DECISIONS LOCKED BY 0.2
--------------------------------------------------------------------------------
  D1. Data root is fixed:
        D:\HAN\Semester 7 Minor\billiards-game-clips\
      This is the single source of truth for all video assets.

  D2. Data root is partitioned by ownership:
        game1\  - source clips + cloth reference images. Read-only.
        IAI\    - IAI-only writes. IPO never reads or writes.
        IPO\    - IPO-only writes (logs, recordings, screenshots).
      Cross-owner writes are forbidden.

  D3. No shared\ folder. IPO reads clips directly from game1\.
      Reason: game1\ already exists, contains the 5 clips, and is used by
      IAI as well. A parallel shared\clips\ would duplicate ~640 MB and
      create a drift risk.

  D4. No reference_frame.png required. Cloth HSV sampling will use:
        game1\clothColor_noAspectRatio.png  (visual reference)
        game1\clothColor_rawPixelValueSet.txt  (numeric HSV triple)
      Reason: reference frame already exists and carries the finalized
      pixel set. Re-sampling is unnecessary and would introduce noise.

  D5. Code repo name: Ball-Type-Identifier (not BilliardClassifier).
      All designTracker / devTracker references updated to this name.

  D6. .gitignore scope:
        build/
        *.exe
        outputs/
      Reason: outputs/ is a decoy inside the repo; real outputs go to
      data-root IPO\*. Build artefacts and binaries must never be pushed.

  D7. Two-workstation sync contract:
        - Code: git pull / push per workstation.
        - Data: hardware-only; not synced via git.
        - Paths in config.h point at the canonical data root. No absolute
          paths inside src/ other than the single DATA_ROOT constant.

  D8. IPO does NOT produce a preprocessed dataset.
      Its pipeline is real-time; only writes recordings/, screenshots/,
      logs/ under the data-root IPO\ tree. No per-ball crops are cached.

  D9. IAI data is usable by IPO ONLY as offline calibration evidence for
      choosing white_ratio / edge_density thresholds. It is never read at
      runtime by the C++ pipeline. Rationale:
        - IAI crops are numeral ROIs; IPO needs whole-ball ROIs.
        - IAI labels are 1..15; IPO labels are CUE / SOLID / STRIPE.
        - IAI features are numeral-shape; IPO features are white-fraction
          and edge-density.
      Runtime coupling would be semantically wrong and would break
      independence if IAI's crop strategy changes.
