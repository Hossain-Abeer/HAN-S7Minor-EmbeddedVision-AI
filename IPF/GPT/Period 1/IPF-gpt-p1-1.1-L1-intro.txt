2.1  DIGITAL IMAGE — definitions, classes, bit depth
--------------------------------------------------------------------------------
Definition
  A digital image is a finite 2D array of picture elements (pixels). Each
  pixel holds one or more numerical samples of a continuous 2D intensity
  function f(x, y), where x, y are spatial coordinates and f is the value
  returned by the sensor (irradiance → charge → digitized voltage).

  Formal:   f_dig[m, n],  m = 0..M-1,  n = 0..N-1
            image dimensions: M rows × N columns

Coordinate conventions (they matter)
  - (row, column) origin top-left. Row increases downward.
  - MATLAB is 1-based: first pixel is (1, 1).
  - The classic "spatial coordinate" convention (x, y) swaps row/column:
    x = column, y = row. IPT is inconsistent about this — Q10-1 exploits it.
  - Pixels sit at integer (row, col). Continuous coordinates fall between
    integer positions; interpolation (L5) estimates f between pixel centres.

Image types in the course
  Binary     : pixel ∈ {0, 1}.  Masks, morphology output, BW images.
  Grayscale  : pixel ∈ [0, 255] uint8; [0, 65535] uint16; [0, 1] double.
  RGB        : 3 planes (R, G, B), each M × N.
  Indexed    : M × N integer index into an L × 3 colormap (memory-saving).
  HSV / HSI  : hue-saturation-value/intensity; perceptual, not device RGB.

  [NEW — L1 slide 14 caveat] L1 prints the grayscale range as "0 - 256".
  That is a typo for 0–255. 8-bit = 2^8 = 256 DISTINCT values counting 0.
  Use 0–255 in every file-size and histogram calculation.

Bit depth — the arithmetic you must know cold
  b bits per pixel → 2^b distinct values.
    1 bit   →    2 values   (binary)
    3 bit   →    8 values
    8 bit   →  256 values   (standard grayscale, uint8)
   10 bit   → 1024 values
   12 bit   → 4096 values
   16 bit   → 65536 values  (uint16)
  Memory per pixel: b/8 bytes. 8-bit = 1 B; 16-bit = 2 B; RGB 8-bit = 3 B.

  Physical meaning: 8-bit does not mean "8 photons". It means 256 quantized
  intensity steps spanning the sensor's usable range. A 12-bit sensor
  distinguishes 16× finer intensity changes than an 8-bit one; that is why
  scientific/machine-vision cameras use 10- or 12-bit ADCs.

  [NEW — L1 slide 22] "8 bits represents 256 values (=2^8)" is stated
  verbatim on the slide.

True colour file cost
  RGB 24-bit per pixel = 8 bit × 3 channels = 3 bytes / pixel.
  An M × N RGB image therefore consumes 3·M·N bytes in memory (before header).

2.1c  COLOUR FORMATS  (subtractive vs additive, indexed, perceptual, L*a*b)
--------------------------------------------------------------------------------
[NEW — L1 slide 14: subtractive vs additive]
SUBTRACTIVE (paint/pigment)             ADDITIVE (light)
  Mixing pigments removes wavelengths.    Mixing light sums wavelengths.
  Primaries: Cyan, Magenta, Yellow.       Primaries: Red, Green, Blue.
  K = black (key) plate.                  R + G + B = white.

  RGB storage: 3 planes, each M × N, each 0–255 uint8 → 24-bit true colour.
  Total colours = 256³ = 16 777 216. Memory = 3·M·N bytes.

[NEW — L1 slide 15: indexed image]
  Each pixel stores a small integer (the index) into an L × 3 colormap.
  Saves memory and storage (b bits/pixel, not 24).
  L1's exact wording: "Saves memory / Saves storage space."
  MATLAB: [X, map] = imread('trees.tif');

[NEW — L1 slide 16: perceptual colour space]
  Hue         (NL: kleurtoon)     — the pure colour, an angle.
  Saturation  (NL: verzadiging)   — colourfulness (0 = grey).
  Brightness / Value / Lightness  — perceived intensity.
  Three names for the same three-axis idea: HSI, HSL, HSV.

[NEW — L1 slide 17: brightness formula]
      Y  =  0.2989·R  +  0.5870·G  +  0.1140·B
  Weights match human cone sensitivity (green strongest, blue weakest);
  these are the weights used by MATLAB's rgb2gray.

[NEW — L1 slide 17: L*a*b colour space]
  L = lightness; a, b = opponent-colour axes.
  Device-independent — same numeric value = same perceived colour across
  monitors/printers. Used for colour matching rather than RGB.

[NEW — L1 slide 21b: "Color's saturation"]
  Two side-by-side patches: LOW saturation (washed-out, near grey) vs
  HIGH saturation (vivid). In HSI: S = 1 − min(R,G,B)/max(R,G,B).
  S = 0 for grey; S = 1 for a pure hue.

2.1f  BITPLANE SLICING AND "LEAST SIGNIFICANT BIT"
--------------------------------------------------------------------------------
[NEW — L1 slide 23: bitplanes]
  An 8-bit image decomposes into 8 binary planes, bit 0 (LSB) to bit 7
  (MSB). Two standard uses:
    • Drop low planes (noise, imperceptible) → simple lossy compression.
    • Keep only the MSB plane → strongest 1-bit silhouette of the image.

[NEW — L1 slide 25: LSB annotation]
  Bit b = 0 of each pixel = smallest intensity increment the quantizer can
  resolve = one quantization step q. Losing the LSB plane is often invisible
  to the eye but not to downstream arithmetic.

2.2  DIGITIZATION = SAMPLING + QUANTIZATION  (two independent discretizations)
--------------------------------------------------------------------------------
The continuous scene is a function f: R² → R. Digitization discretizes
BOTH domains:

  Spatial domain   (x, y)  → discrete grid     → SAMPLING
  Amplitude domain  f      → discrete levels   → QUANTIZATION

Order (from the syllabus): usually sampling first, then quantization.

SAMPLING — full picture
  - 1D view: continuous g(t) sampled at t = nT_s → g[n].
    Sampling rate f_s = 1/T_s, samples per second (or per mm in 2D).
  - 2D view: Δx and Δy are spatial step sizes along each axis.
    f[m, n] = f_continuous(m·Δx, n·Δy).
  - Two parameters (L1 lists both explicitly):
      * sampling RATE    = number of samples per unit length (dpi, ppi).
      * sampling PATTERN = physical arrangement (rectangular grid most
                           common; hexagonal or Bayer patterns exist).
  - Higher sampling rate → more pixels → higher spatial resolution → finer
    detail captured. Memory grows as the square of the rate.

QUANTIZATION — full picture
  - Continuous intensity is mapped to L = 2^b discrete levels.
  - Step size: q = (max − min) / L  for uniform quantization.
  - Every pixel value is snapped to the nearest multiple of q (plus offset).
  - Higher b → finer steps → smoother gradients, less banding, bigger files.

  Bit-depth visual effect
    Low-bit images (2–3 bit) show visible contouring: smooth gradients become
    stair-stepped bands. 8-bit is industry standard because it just hides this
    from the human eye at normal viewing.

  Interaction between the two
      1024 × 1024, 1 bit   → very sharp spatial detail, harsh intensity
        64 × 64, 256 levels → smooth intensity, chunky spatial blocks
    Both are "digital images" — they trade off different information.

2.3  SPATIAL RESOLUTION  (measured in dpi / ppi)
--------------------------------------------------------------------------------
Definition
  Number of pixels per unit physical length in the captured image.
     dpi  = dots per inch (print)
     ppi  = pixels per inch (display)
  For a fixed physical scene, higher dpi = more pixels = finer detail, but
  memory grows as (rate)².

Why resolution alone does not guarantee detail
  Resolution on the sensor is meaningless without FIELD OF VIEW (L2). A
  4096-pixel sensor on a 10 m FOV has ~2.4 mm/pixel; the same sensor on a
  10 cm FOV has ~24 μm/pixel.

Bad-resolution artefacts (from L1)
  - Pixelation      : individual pixels become visible blocks.
  - Jaggedness      : diagonal edges appear stair-stepped.
  - Loss of detail  : fine features vanish (football.jpg / text.png).
  - Moiré patterns  : interference between scene frequency and sampling grid.

Rule of thumb in machine vision
  Feature of interest should span ≥ 2–3 pixels to be reliably detected —
  this links back to Nyquist for spatial sampling.

2.3b  HUMAN VISION AND PERCEPTUAL LIMITS
--------------------------------------------------------------------------------
[NEW — L1 slides 19–22: human vision]
  L6 (image enhancement) is defined as "improve subjective quality for a
  human viewer". The eye model is therefore part of L1, not L2.

  Anatomy numbers (memorise):
      Focal length of the human eye        f = 14 to 17 mm
      Cones (colour, three types S, M, L)  ≈ 6–7 million
      Rods  (low light, no colour)         ≈ 75–150 million
      Fovea (sharpest-vision region)        1.5 × 1.5 mm²
      Fovea density                         150 000 elements / mm²

  [NEW — L1 slide 22: spectral sensitivity]
  Three cone cell types — Short (S), Medium (M), Long (L) — absorb
  preferentially at different wavelengths. The R/G/B weighting in the
  brightness formula (0.2989·R + 0.5870·G + 0.1140·B, §2.1c) comes
  directly from these three response curves.

  L1's bridge claim (slide 19): "ability of eye to resolve detail is similar
  to electronic imaging sensors." The eye, like a camera, is a spatial
  sampler subject to the Nyquist limit of its own sample spacing.

  OPTICAL ILLUSIONS  [NEW — L1 slides 20–21]
    Checker-shadow illusion — E. H. Adelson (slide 21). Two pixels with the
    same numeric RGB value look different because the brain discounts
    perceived illumination. Meaning for image processing: human brightness
    perception ≠ pixel intensity. "Enhance for a human" (histogram
    equalisation, gamma) is not the same as "preserve intensity" (identity,
    linear stretch).

  WEBER'S LAW  [NEW — L1 slide 22]
        ΔI / I  ≈  1 – 2 %
    with I = luminance in cd/m². The just-noticeable-difference in luminance
    is a fraction of the background, not an absolute amount. A 1-unit step
    on I = 10 is far more visible than the same step on I = 200. This is the
    psychophysical justification for log and gamma transforms (L6): they
    compress bright ranges so ΔI stays near Weber's constant across the
    display range.

2.4  ALIASING AND THE NYQUIST THEOREM
--------------------------------------------------------------------------------
Mechanism of aliasing (be precise about the "why")
  Sampling a sinusoid at frequency f_signal with sample rate f_s produces an
  observed frequency that is "folded" back into the baseband [0, f_s/2]:

     f_observed = | f_signal  −  k · f_s |      for the integer k that brings
                                                f_observed into [0, f_s/2].

  When f_signal > f_s/2 the folded f_observed is smaller than f_signal and the
  reproduction looks WRONG — a slower oscillation masquerading as the real one.
  The f_s/2 boundary is called the NYQUIST FREQUENCY (or fold-over frequency).

Nyquist criterion
  To reconstruct a signal faithfully, we must sample STRICTLY ABOVE twice the
  highest frequency present in the scene:

        f_s  >  2 · f_max

  If the criterion is met, an ideal low-pass reconstruction filter recovers
  f(t) exactly. If it is violated, information is lost irreversibly — no
  post-processing can recover the original.

Anti-aliasing (the pre-filter)
  Before sampling at rate f_s, apply a low-pass filter with cutoff ≤ f_s/2.
  This removes the high frequencies that would otherwise fold. imresize
  (bilinear/bicubic) applies an internal low-pass filter when shrinking —
  but NEAREST-neighbour imresize does NOT, which is the trap of sample-exam
  Q5.

Three canonical aliasing examples (memorize at least two)
  1. Wagon-wheel effect (TEMPORAL aliasing). Spoked wheel rotating at rate
     r seen at 30 fps appears to rotate backwards when r exceeds the Nyquist
     rotation rate — the sampled "frames" under-sample the real motion.
  2. Moiré pattern (SPATIAL aliasing). Two periodic patterns (scene and
     pixel grid) beat at a low frequency, producing false large-scale
     stripes — visible in scanned fabric, brick walls, sub-sampled
     checkerboards.
  3. Text/image sub-sampling. Downsampling a sharp text image by factor M
     without pre-filtering produces jagged, unreadable letters — the
     football.jpg / text.png exercise in syllabus §3.

Spatial-sampling equivalent of Nyquist
  Feature of size d in the scene must be sampled by pixel size p ≤ d/2.
  Equivalently: at least two samples per feature diameter. This is the exact
  statement sample-exam Q1 computes when it asks for "line pairs per mm".

[NEW — L1 slide 36: wagon-wheel effect, verbatim]

2.5  NEIGHBOURHOODS — N4, ND, N8  (depth)
--------------------------------------------------------------------------------
Fix a central pixel p = (x, y).

3 × 3 NEIGHBOURHOOD  (the "Moore stencil")
  - The complete local window of 9 pixels centred on p.

          (x-1, y-1)   (x-1, y)   (x-1, y+1)
          (x,   y-1)   (x,   y)   (x,   y+1)
          (x+1, y-1)   (x+1, y)   (x+1, y+1)

  - Standard support for 3×3 filters (convolution, median, Sobel, Prewitt,
    Laplacian, hit-or-miss). Larger stencils (5×5, 7×7) generalise.

4-NEIGHBOURHOOD  N4(p)
  - 4 pixels that share an EDGE with p — north, south, east, west:
        (x-1, y),  (x+1, y),  (x, y-1),  (x, y+1)
  - Euclidean distance = 1; city-block distance = 1.
  - Basis of 4-adjacency and the city-block metric.

DIAGONAL NEIGHBOURHOOD  ND(p)
  - 4 pixels that share only a CORNER with p:
        (x-1, y-1),  (x-1, y+1),  (x+1, y-1),  (x+1, y+1)
  - Euclidean distance = √2 ≈ 1.414; city-block distance = 2.

8-NEIGHBOURHOOD  N8(p)  (Moore neighborhood)
  - Union: N8(p) = N4(p) ∪ ND(p)
  - All 8 pixels that touch p (edge or corner).
  - Chessboard distance: max(|Δx|, |Δy|).

Metric summary

        Neighbourhood     metric           distance to neighbours
        ------------      ---------------  -----------------------
        N4                city-block (L1)  1
        ND                —                √2  (Euclid); 2 (city-block)
        N8                chessboard (L∞)  max(|dx|,|dy|) = 1

  These metrics reappear:
    - bwdist(a,'cityblock') in L12 distance transform.
    - bwperim(..., 8) vs bwperim(..., 4) in L10.
    - bwlabel(..., 8) vs bwlabel(..., 4) in L10/L13.
    - regionprops Euler number depends on the connectivity used.

2.6  ADJACENCY — 4-, 8-, and m-adjacency
--------------------------------------------------------------------------------
Set V (the allowed values)
  V = {set of pixel values permitted on a path}. E.g. V = {1} means we may
  only step on pixels whose value is 1. When the question says "V = {0,1}",
  both 0-valued and 1-valued pixels are legitimate steps. This is why
  sample-exam Q6 uses V = {0,1} — background pixels count.

4-ADJACENCY
  Two pixels p and q are 4-adjacent iff:
        q ∈ N4(p)   AND   p, q ∈ V.
  Local, symmetric. Unit-step distance 1.

8-ADJACENCY
  Two pixels p and q are 8-adjacent iff:
        q ∈ N8(p)   AND   p, q ∈ V.
  Still local and symmetric, now allows diagonal steps. Problem: it can
  create AMBIGUOUS paths — two different paths between same endpoints with
  same length. In connected-component analysis this inflates region counts
  and thickness.

m-ADJACENCY  (mixed, eliminates the ambiguity)
  Two pixels p and q are m-adjacent iff (both in V and):

        (i)   q ∈ N4(p),   OR
        (ii)  q ∈ ND(p)  AND  N4(p) ∩ N4(q) = ∅.

  Translation: a diagonal step is allowed ONLY when the two orthogonal
  pixels between p and q are NOT both already in V. If they are, the
  diagonal step would create a redundant path that 4-adjacency already
  provides — so m-adjacency forbids it, forcing the unambiguous route.

  Geometric picture for a diagonal step from p to q:
        p   a
          q           a = (x, y+1), b = (x+1, y).
        b
     The diagonal p → q is m-legal  ⟺  at least one of {a, b} ∉ V.
     If BOTH a and b are in V, the "cleaner" path p → a → q or p → b → q
     already exists; the diagonal is redundant.

Worked rule of thumb
  With V = {1} and a solid 3×3 block of 1s, m-adjacency behaves like
  4-adjacency for path-length purposes: diagonals inside the block are
  forbidden because their two edge-neighbours are also 1s. On the boundary
  of the block the diagonal is usually allowed because one edge-neighbour
  is background.

2.7  PATHS  (formal definition + length)
--------------------------------------------------------------------------------
Definition
  A digital path (or curve) from p with coordinates (x, y) to q with (s, t)
  is a sequence of DISTINCT pixels:

        (x0, y0), (x1, y1), …, (xn, yn)

  such that:
      (x0, y0) = p,   (xn, yn) = q,
      and consecutive pairs (x_i, y_i), (x_{i-1}, y_{i-1}) are adjacent
      under the chosen adjacency rule (4, 8, or m).

Length
  n = number of steps. (Not number of pixels — number of transitions.)
  A path with k pixels has length k − 1.

Closed path
  If (x0, y0) = (xn, yn), the path is closed (a loop).

Distinctness clause
  "Distinct pixels" is what makes paths finite; without it you could cycle
  forever. It also means paths in adjacency questions are the SHORTEST
  simple path.

4-, 8-, m-path
  A path whose steps obey 4-, 8-, or m-adjacency respectively.
  Property (exam-relevant): length_4 ≥ length_m ≥ length_8.
  Equality holds when no diagonal shortcut is available or, for m, when
  all diagonal shortcuts are blocked by both edge-neighbours being in V.

2.8  CONNECTIVITY, COMPONENTS, REGIONS, BOUNDARIES
--------------------------------------------------------------------------------
Adjacency vs connectivity
  ADJACENCY   : local, pairwise relation. p and q are adjacent if their
                pixels satisfy the (V, rule) test directly.
  CONNECTIVITY: transitive closure of adjacency. p and q are connected if
                there EXISTS a path of adjacent pixels between them.

Formal
  p ~ q  iff  there exists a path (per chosen adjacency) from p to q.
  "~" is an equivalence relation. Its equivalence classes are the connected
  components.

Connected component
  A maximal set of pixels that are all mutually connected under the chosen
  adjacency. Using 8-adjacency merges more diagonal-touching clusters than
  4-adjacency does. This directly changes:
     - number of components (bwlabel 4 vs 8)
     - Euler number = (# components) − (# holes) in L13 regionprops
     - boundary pixel counts in bwperim 4 vs 8 (L10)

Region vs boundary
  REGION  = a connected component inside the image, usually interpreted as
            "one object".
  BOUNDARY= outer pixels of a region. Internal boundary pixels touch
            background inside the region (holes); external touch background
            outside. L10 defines "morphological gradient" as (dilate − erode)
            — union of internal and external boundaries.

Why this matters downstream (one line each)
  L10 morphology: dilation/erosion defined via N4/N8 stencils; bwlabel
       counts depend on adjacency choice.
  L12 segmentation: region growing stops when neighbours fail predicate;
       the "neighbour" set is N4 or N8.
  L13 features: Euler number and perimeter are connectivity-dependent.
  Sample-exam Q6: directly tests 4-, 8-, m-path lengths.

5. FORMULA / DEFINITION BOX
--------------------------------------------------------------------------------
Digitization:        image  =  sampling  +  quantization
Bit depth:           b bits → 2^b levels → b/8 bytes/pixel
File size:           bytes = M·N·(b/8) + header
Brightness (L1):     Y = 0.2989·R + 0.5870·G + 0.1140·B
Saturation (HSI):    S = 1 − min(R,G,B)/max(R,G,B)
Weber's law:         ΔI / I ≈ 1 – 2 %,  I in cd/m²
Nyquist:             f_s > 2·f_max
Aliased frequency:   f_obs = | f_signal − k·f_s |,  k = round(f_signal/f_s)
N4(p):               {(x−1,y),(x+1,y),(x,y−1),(x,y+1)}
ND(p):               {(x−1,y−1),(x−1,y+1),(x+1,y−1),(x+1,y+1)}
N8(p):               N4(p) ∪ ND(p)
4-adjacency:         q ∈ N4(p)   ∧ p,q ∈ V
8-adjacency:         q ∈ N8(p)   ∧ p,q ∈ V
m-adjacency:         q ∈ N4(p) ∨ ( q ∈ ND(p) ∧ N4(p) ∩ N4(q) = ∅ )
Euclidean:           D = sqrt(Δx² + Δy²)
City-block:          D = |Δx| + |Δy|
Chessboard:          D = max(|Δx|, |Δy|)
Path length:         n = #steps = #pixels − 1
Connectivity:        p ~ q  iff  ∃ path (V, rule) from p to q
Euler number:        E = (# components) − (# holes)

EXAMPLE A — Euclidean distance  (syllabus Q2-6)
--------------------------------------------------------------------------------
Grid (rows 1..4, cols 1..4). p at (1,1), q at (4,3):
         p  .  .  .
         .  .  .  .
         .  .  .  .
         .  .  q  .

  Δrow = 4−1 = 3,   Δcol = 3−1 = 2
  D    = sqrt(3² + 2²) = sqrt(9 + 4) = sqrt(13) ≈ 3.606

  Also: city-block = 3+2 = 5, chessboard = max(3,2) = 3.
  The exam wants the Euclidean answer unless specified.

EXAMPLE B — 4-, 8-, m-path lengths with V = {1}
--------------------------------------------------------------------------------
Grid:
        1  1  0
    p→  1  1  0
        1  1  q    q at (3,3); p at (2,1)

  4-PATH from p
    p(2,1) → (2,2) → (3,2) → (3,3)=q        length 3.
    Alternative: p → (3,1) → (3,2) → q      length 3.
    Result: length 3.

  8-PATH from p
    p(2,1) → (3,2) [diagonal] → q(3,3)      length 2.
    Result: length 2.

  m-PATH from p
    Check the diagonal step (2,1) → (3,2):
      N4(p) = {(1,1),(3,1),(2,2)}
      N4((3,2)) = {(2,2),(3,1),(3,3)=q}
      Intersection = {(2,2),(3,1)} ≠ ∅  →  diagonal FORBIDDEN by m-rule.
    Fall back to 4-style step:
      p → (2,2) → (3,2) → q                length 3.
    Result: length 3.

  Answer: 4-path = 3, 8-path = 2, m-path = 3.
  Sample-exam Q6 uses this exact pattern — sometimes m equals 4, sometimes
  m is a mixed value between 4 and 8 depending on the layout.

EXAMPLE C — file size
--------------------------------------------------------------------------------
(a) 1024 × 1024, 8-bit grayscale, 32-byte header.
    bytes = 1024 · 1024 · 1 + 32 = 1,048,576 + 32 = 1,048,608.

EXAMPLE D — Nyquist
--------------------------------------------------------------------------------
A scene contains a periodic pattern with 5 line-pairs per mm. Minimum required
sampling density (in samples/mm)?

    Line-pair = 1 bright + 1 dark stripe = one full period.
    f_max (spatial) = 5 line-pairs/mm.
    Nyquist: f_s > 2 · f_max → f_s > 10 samples/mm.
    In samples per line-pair: 2 samples per line-pair minimum.

  This is sample-exam Q1 logic: convert sensor elements per mm to line-pairs
  per mm by dividing by 2.

EXAMPLE E — L1 slide 41 quantization demonstration
--------------------------------------------------------------------------------
[NEW — L1 slide 41]
  Original image: 8-bit grayscale, file size 906 390 bytes.
  Requantised:    3-bit grayscale, file size 214 727 bytes.
  Ratio ≈ 4.22 (not 8/3 = 2.67) because of fixed header + per-row padding.
  Lesson: lower bit depth saves bytes but not proportionally when the header
  is fixed. For file-size exam questions always use b/8 formula + header.

Q3-6  Describe aliasing and its relation to the Nyquist frequency.
  [Verbatim summary; full text spans two PDF pages:]

  "The Nyquist Theorem, also known as the sampling theorem, is a principle
   that engineers follow in the digitization of analog signals. For
   analog-to-digital conversion to result in a faithful reproduction of the
   signal, slices, called samples, of the analog waveform must be taken
   frequently. The number of samples per second is called the sampling rate
   or sampling frequency.

   Any analog signal consists of components at various frequencies. The
   simplest case is the sine wave, in which all the signal energy is
   concentrated at one frequency. In practice, analog signals usually have
   complex waveforms, with components at many frequencies. The highest
   frequency component in an analog signal determines the bandwidth of that
   signal. The higher the frequency, the greater the bandwidth, if all other
   factors are held constant.

   Suppose the highest frequency component, in hertz, for a given analog
   signal is fmax. According to the Nyquist Theorem, the sampling rate must
   be at least 2 × fmax, or twice the highest analog frequency component.
   The sampling in an analog-to-digital converter is actuated by a pulse
   generator (clock). If the sampling rate is less than 2 × fmax, some of
   the highest frequency components in the analog input signal will not be
   correctly represented in the digitized output. When such a digital
   signal is converted back to analog form by a digital-to-analog converter,
   false frequency components appear that were not in the original analog
   signal. This undesirable condition is a form of distortion called
   aliasing.

   A first result of aliasing is the formation of Jaggies. 'Jaggies' is the
   informal name for artifacts in raster images, most frequently from
   aliasing. Jaggies are stairlike lines that appear where there should be
   smooth straight lines or curves.

   A special case of aliasing, due to undersampling a fine regular pattern,
   is the formation of Moire patterns (Figure 2)."
  [note] PDF Figure 2 is "Aliasing and the formation of Moire patterns."
