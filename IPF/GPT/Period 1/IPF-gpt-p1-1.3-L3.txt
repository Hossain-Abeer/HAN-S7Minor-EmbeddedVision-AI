1. ESSENCE
--------------------------------------------------------------------------------
L3 does three things at once. (a) It establishes MATLAB as the working tool
for the course: what it is (matrix laboratory), why it is used (rapid,
matrix-native, image toolbox), and how it is organised (command window,
workspace, scripts, functions, Simulink). (b) It lays down the data classes
that the rest of the course depends on — uint8, double, logical — because
every later "image" is one of those three at heart. (c) It teaches the
small set of MATLAB idioms you will read on the exam: function syntax,
H1 help line, anonymous functions, for/while/if/switch, tic/toc, vectorized
expressions, and the IPT's display/conversion/arithmetic wrappers
(imread, imshow, imtool, im2double, imadd, imsubtract). Reading the code
is the exam skill; running it is not required.

2.2  THE WORKING ENVIRONMENT
--------------------------------------------------------------------------------
[L3 slide 12]
Five visible panes, one per function:
  Current directory   — file browser for the working folder.
  Script files        — open .m files, editor tabs.
  Workspace variables — list of all variables currently in memory.
  Preview             — highlighted variable contents.
  Command Window      — REPL; where you type commands and see output.

  The distinction the exam expects:
    *Command Window*  — interactive, one-shot statements.
    *Script (.m file)* — saved, reusable sequence of statements.
    *Function (.m file)* — saved, reusable, parameterised.
  The syllabus §5 assumes all three are known.

2.3  SIMULINK (block-diagram counterpart)
--------------------------------------------------------------------------------
[L3 slides 13–14]
Simulink is MATLAB's block-diagram environment. The comparison on the slide:

  Code (script)                         Block diagram (Simulink)
  f = imread('belgie (247).jpg');       open_system('rotate_image_model');
  g = imrotate(f, pi/6 * 180/pi);       cs = getActiveConfigSet(model);
  imshow(g);                            set_param(..., 'Angle', 'pi');
                                        SimOut = sim(model, cs);

  Key differences:
    • Code executes line by line.
    • Diagram executes on a clock; each block runs once per sample.
    • The two can call each other: scripts can invoke Simulink models with
      sim() and read out SimOut.

  Exam-relevant: Simulink appears only as "MATLAB has a block-diagram
  counterpart". Not asked in exam detail; expected to know it exists.

2.4  ESSENTIAL MATLAB COMMANDS
--------------------------------------------------------------------------------
[L3 slide 15]
These are the commands the course assumes you can read on sight:

  help                  — display help text in Command Window.
  chdir('...')          — change working directory.
  imread('test.png')    — read image file into a variable.
  imwrite(img2, ...)    — write image variable to a file.
  imshow(img)           — display image (optimised, no axes artefacts).
  imshowpair(a, b, 'montage') — side-by-side display of two images.
  clc                   — clear Command Window.
  clear all             — clear Workspace variables.
  close all             — close all figures.
  print(figure(3), ...) — save figure as PNG with DPI control.
  iptdemos              — launch Image Processing Toolbox demos.

  The trio "clc; clear all; close all" is the standard reset at the top
  of every exercise script in the syllabus. The exam assumes you know
  which part resets what: clc → window; clear all → variables;
  close all → figures.

2.5  DATA CLASSES
--------------------------------------------------------------------------------
[L3 slides 17–18]
Top-level array classes (slide 17):
  Matrix / Array (full or sparse)
  logical    — {true, false}, 1 byte per element
  char       — characters (text), 2 bytes per element (Unicode)
  numeric    — see table below
  table      — tabular data structure
  cell       — heterogeneous container, indexed by { }
  struct     — keyed container, indexed by .

Numeric subclasses (slide 18, verbatim):

  Name     Description                                                  Bytes
  ------   ---------------------------------------------------------   -----
  double   FP, range ≈ ±10^308                                           8
  uint8    Unsigned 8-bit integer, [0, 255]                             1
  uint16   Unsigned 16-bit integer, [0, 65535]                          2
  uint32   Unsigned 32-bit integer, [0, 4294967295]                     4
  int8     Signed 8-bit integer, [-128, 127]                            1
  int16    Signed 16-bit integer, [-32768, 32767]                       2
  int32    Signed 32-bit integer, [-2147483648, 2147483647]             4
  single   Single-precision FP, range ≈ ±10^38                           4

  Course-only three (memorise the ranges):
    uint8   [0, 255]       — the standard grayscale
    double  [0, 1] (IPT's normalized convention)
    logical {0, 1}         — binary masks

  Why this matters (L1 §2.1 arithmetic): uint8 file size = M·N·1 bytes;
  double = M·N·8; RGB uint8 = 3·M·N.

2.7  STANDARD ARRAY GENERATORS
--------------------------------------------------------------------------------
[L3 slide 20, verbatim]
  zeros(m,n)      m × n matrix of zeros
  ones(m,n)       m × n matrix of ones
  true(m,n)       m × n logical ones
  false(m,n)      m × n logical zeros
  eye(n)          n × n identity matrix
  magic(m)        m × m magic square (rows, cols, diagonals all equal)
  rand(m,n)       uniform pseudo-random in [0, 1]
  randn(m,n)      normal pseudo-random, mean 0, variance 1

  Exam pattern: read a line that uses one of these and predict the class
  of the result.
    zeros(m,n)         → double
    ones(m,n)          → double
    true(m,n)          → logical
    eye(n)             → double
    magic(m)           → double
    rand(m,n)          → double in [0,1]
    randn(m,n)         → double, normally distributed

  Very common exam trap: ones(m,n) returns DOUBLE 1s, not logical.
  If you want logical 1s you must use true(m,n) or cast with logical().

2.8  RELATIONAL AND LOGICAL OPERATORS
--------------------------------------------------------------------------------
[L3 slides 21–22]
Relational (return logical arrays):
  <    less than
  <=   less than or equal
  >    greater than
  >=   greater than or equal
  ==   equal to
  ~=   not equal to

Logical (element-wise on logical arrays):
  &    AND
  |    OR
  ~    NOT

Function-form logical operators:
  xor(a, b)   — exclusive-OR between operands.
  all(v)      — 1 if all elements nonzero, else 0. Columnwise on matrices.
  any(v)      — 1 if any element nonzero, else 0. Columnwise on matrices.

  Exam-relevant distinction (links to L4 arithmetic):
    • logical AND &     — on binary masks
    • bitwise AND bitand — on grayscale/colour pixel bits
  L3 only introduces the logical operators; the bitwise functions
  bitand, bitor, bitxor, bitcmp, imcomplement are formally introduced in
  L4. Reading L3 covers the syntax; L4 covers the application.

2.9  BUILT-IN VARIABLES AND CONSTANTS
--------------------------------------------------------------------------------
[L3 slide 23, verbatim]
  ans      most recent answer
  eps      floating-point relative accuracy (≈ 2.2204e-16 for double)
  i or j   imaginary unit = sqrt(-1)
  NaN      Not-a-Number (e.g. 0/0)
  Inf      Infinity (e.g. 1/0)
  pi       π
  clock    date and time vector [year month day hour min sec]
  date     current date string

  Exam trap: i and j are constants, but they are NOT reserved. Assigning
  i = 5 in a script silently overwrites the imaginary unit — this is the
  source of the syllabus Q5.6 answer "these variables can be overwritten
  and changed back to their original value; clear all is used to reset".

  eps: distance from 1.0 to the next larger double; not "smallest
  positive number". realmin and realmax are the actual smallest/largest
  finite doubles (see Q5.2).

2.10  ARITHMETIC OPERATORS — MATRIX vs ELEMENT-WISE
--------------------------------------------------------------------------------
[L3 slides 24–25]
  Operator   Meaning                              Function form
  --------   ----------------------------------   -------------
  +          array and matrix addition            plus(a,b)
  -          array and matrix subtraction         minus(a,b)
  .*         element-by-element multiplication    times(a,b)
  *          matrix multiplication                mtimes(a,b)
  ./         array right division                 rdivide(a,b)
  .\         array left division                  ldivide(a,b)
  /          matrix right division                mrdivide(a,b)
  \          matrix left division                 mldivide(a,b)
  .^         array power                          power(a,b)
  ^          matrix power                         mpower(a,b)
  .'         vector/matrix transpose              transpose(a)
  +          unary plus                           uplus(a)
  -          unary minus                          uminus(a)

  The dot prefix (".*", "./", ".^") is the single most exam-critical
  rule in L3. Element-wise vs matrix is the difference between "multiply
  each pixel by each pixel" (element-wise) and "linear-algebra matrix
  product" (matrix).
  Rule of thumb: for image work, you almost always want .*, ./, .^ — the
  element-wise forms. Matrix * and ^ appear in rotations and in solving
  linear systems.

2.11  SCRIPTS AND FUNCTIONS
--------------------------------------------------------------------------------
[L3 slides 26–28]
Three kinds of .m files:
  Script    — a plain sequence of statements. No parameters. Runs top-to-
              bottom on the caller's workspace. Variables leak into base
              workspace.
  Function  — declared with "function [outputs] = name(inputs)". Has its
              own private workspace. Callable from scripts or the command
              window.
  Anonymous — one-line function stored in a variable, no separate file.
              Syntax: sqr = @(x) x.^2; then sqr(5) → 25.

Function file structure (slide 27, verbatim):
  • Function definition line
        function [outputs] = function_name(inputs)
  • H1 line — single comment line immediately after the definition.
    Shown first when you type "help function_name".
  • Help text — block of comment lines after the H1 line. Shown after the
    H1 line when you type "help function_name".
  • Function body — all MATLAB code performing computation and assigning
    outputs.

  Why the H1 + help text matter (Q6.5): MATLAB treats the FIRST
  comment block after the function definition line as help documentation.
  Comments elsewhere in the file are not returned by help.

Anonymous function (slide 28):
  sqr = @(x) x.^2;
  a = sqr(5);       % a = 25
  The @ symbol is the function handle; inside, x is the formal parameter.
  Anonymous functions are used heavily in L9 and L13 for passing short
  operations to nlfilter, blockproc, and cellfun.

2.12  CONTROL STATEMENTS
--------------------------------------------------------------------------------
[L3 slides 29–33]
Four control structures, each with its documented diagram on the slide:

  FOR loop (slide 30)
    for j = 1:10
        % computations
    end
    Repeats a fixed number of times. The slide emphasises "always executes
    computation loop at least once" — that phrasing is a slight
    oversimplification but is what the slide says. Break exits early.

  WHILE loop (slide 31)
    k = 0;
    while k < 10
        % computations
        k = k + 1;
    end
    Runs while the condition is true. Danger: if k is never updated, this
    loops forever. Initialise the condition variable BEFORE the loop.

  IF / IF-ELSEIF / IF-ELSE (slides 32–33)
    if condition
        ...
    elseif another
        ...
    else
        ...
    end
    Multiple elseif conditions allowed. else is optional. Condition
    statements may be logical operators (&, |, ~) or relational (<, ==,
    etc.). if statements can nest.

  SWITCH-CASE (slide 33)
    switch expr
        case value1
            ...
        case value2
            ...
        otherwise
            ...
    end
    Matches expr against the cases; otherwise is the default.

  Exam-relevant reading skill: predict what happens when a for loop has
  an off-by-one boundary (1:n vs 0:n-1 vs 1:n+1). Common trap in L13's
  "for k = 1:N" loops where N is the number of objects.
  Vectorization replaces loops in most image-processing idioms — see
  §2.13.

2.13  TIMING AND VECTORIZATION
--------------------------------------------------------------------------------
[L3 slides 34–35]
  TIC / TOC
    tic starts a stopwatch; toc returns elapsed seconds.
    Standard idiom for comparing loop vs vectorized implementations.

  PROFILE ON / PROFILE VIEWER
    profile on     — starts a profiler that records per-function time.
    profile viewer — opens the profiler GUI.
    profile off    — stops.

  MULTITHREADING
    MATLAB automatically parallelises many built-in operations. The slide
    mentions it as the reason vectorized code often beats a hand-written
    loop even on a single core.

  VECTORIZATION (the central rule):
    Instead of
        x = zeros(1, 10000);
        for i = 1:10000
            x(i) = i^2;
        end
    write
        i = 1:10000;
        x = i .^ 2;
    The .^ is essential. Without the dot, MATLAB tries a matrix power and
    fails (or does something unintended).

  Preallocation (a secondary rule):
    x = zeros(1, 10000); before filling x(i) in a loop avoids repeated
    memory reallocation. Syllabus Q6.6 measures this as ~7–8× speedup
    on 10000 elements.

2.14  IPT ESSENTIAL FUNCTIONS — CONVERSIONS
--------------------------------------------------------------------------------
[L3 slides 37–38]
Data classes and conversions you must know cold:

  im2single  → single
  im2double  → double, auto-scaled to [0,1] for uint8 input
  im2uint8   → uint8, auto-scaled
  im2uint16  → uint16, auto-scaled
  im2int16   → int16
  ind2gray   → indexed → grayscale
  gray2ind   → grayscale → indexed
  rgb2gray   → RGB → grayscale
  rgb2ind    → RGB → indexed
  ind2rgb    → indexed → RGB

  Critical subtlety (Q7.6, Q9.15): im2double is NOT the same as
  double().
    im2double(uint8(255)) = 1.0000     (scales to [0,1])
    double(uint8(255))    = 255.0000   (just changes the class)
  Same for im2uint8 vs uint8: the "im2" prefix rescales, the bare
  type-name does not.

  The (uint8 → double) conversion is the correct choice when you will
  perform arithmetic that can produce negative values (Laplacian, FFT,
  division) — L7 and L8 rely on this.

2.15  IPT ESSENTIAL FUNCTIONS — DISPLAY
--------------------------------------------------------------------------------
[L3 slide 39]
  image(C)      — display using the current colormap.
  imagesc(C)    — scale C to full colormap range, then display.
  imshow(I)     — IPT-optimised display: handles class, range, colormap.
  imtool(I)     — imshow plus interactive tools (Pixel Region, Image Info,
                  Adjust Contrast).

  Rule for exam: when the code contains imshow and a second argument
  [low high], it auto-scales that range to [0,1] for display.
  imshow(I)                — displays uint8 as [0,255], double as [0,1]
  imshow(I, [])            — scales the actual min/max to [0,255] or [0,1]
  imshow(I, [0 99])        — maps 0 → black, 99 → white, clips the rest

  imtool adds the Pixel Region (zoom on individual pixels), Image
  Information (class, range, dims), and Adjust Contrast (real-time
  histogram stretch). This is the tool used in Q7.7 for interactive
  pixel inspection.

2.16  IPT ESSENTIAL FUNCTIONS — ARITHMETIC
--------------------------------------------------------------------------------
[L3 slide 41, verbatim]
  imadd         add two images, or add a constant to an image
  imsubtract    subtract two images, or subtract a constant
  immultiply    multiply two images (element-wise), or by a constant
  imdivide      divide two images (element-wise), or by a constant
  imabsdiff     absolute difference between two images
  imcomplement  complement (invert) an image
  imlincomb     linear combination of two or more images

  Contrast with bare operators: "I1 + I2" on uint8 images saturates
  silently at 255 and rolls over; "imadd(I1, I2)" saturates deliberately
  (clips at 255) because that is what "brighter" means in uint8.
  "I1 - I2" on uint8 also rolls over; "imsubtract" clips at 0.
  For images in double, imadd/imsubtract and bare + / - behave the same
  way; imabsdiff always returns absolute difference regardless of class.

  Exam-relevant: any exam question that says "what happens at overflow"
  is asking about the difference between imadd (saturates) and + on
  uint8 (wraps). Full treatment in L4 arithmetic.

4. SUMMARY (exam-ready, 12 bullets)
--------------------------------------------------------------------------------
1. MATLAB = MATrix LABoratory; matrix-native language; chosen for rapid
   development, integrated environment, and image toolboxes.
2. Working environment: Current directory, Workspace variables, Command
   Window, Script files, Preview.
3. Reset trio: clc (window), clear all (variables), close all (figures).
4. Three .m file types: script (top-to-bottom, shared workspace), function
   (declared with "function [out] = name(in)", private workspace),
   anonymous (@(x) expr, no file).
5. Data classes: uint8 [0,255], uint16 [0,65535], int8 [-128,127],
   double ±10^308, logical {true,false}. Image work uses uint8, double,
   logical.
6. Standard arrays: zeros, ones, eye, magic, rand (uniform), randn
   (Gaussian), true/false (logical). ones(m,n) returns double, not logical.
7. Arithmetic: .*, ./, .^ are element-wise; *, /, ^ are matrix. Element-
   wise is the image-processing default.
8. Control: for, while, if/elseif/else, switch-case. Preallocation with
   zeros() before a for loop gives ~7–8× speedup. Vectorization usually
   beats both.
9. Built-in constants: pi, eps (≈2.22e-16), i/j (√-1), Inf, NaN, ans.
   Overwritable; reset with clear all.
10. IPT conversions: im2double rescales [0,255]→[0,1]; double() only
    changes class. im2uint8 rescales [0,1]→[0,255]; uint8() only changes
    class.
11. IPT display: imshow (auto class-aware), imshow(I,[]) scales min-max
    to display range; imtool adds interactive pixel/contrast/region tools.
12. IPT arithmetic: imadd, imsubtract, immultiply, imdivide, imabsdiff,
    imcomplement, imlincomb. They saturate at [0,255] for uint8 instead
    of wrapping.

5. FORMULA / DEFINITION BOX
--------------------------------------------------------------------------------
Data class ranges:
  uint8    [0, 255]          logical  {0, 1}
  uint16   [0, 65535]        int8     [-128, 127]
  int16    [-32768, 32767]   double   ≈ ±1e308, precision ≈ 2.22e-16
Element-wise vs matrix:
  .*  element-wise multiply        *  matrix multiply
  ./  element-wise right divide    /  matrix right divide
  .\  element-wise left divide     \  matrix left divide
  .^  element-wise power           ^  matrix power
Function file structure:
  function [out] = name(in)
  % H1 line (one line)
  % help text (comment block)
  ...body...

6. HAND-CALC WORKED EXAMPLES

EXAMPLE A — data-class conversion (im2double vs double)
--------------------------------------------------------------------------------
Given I = uint8(200).

  double(I)     = 200.0000     (class double, value unchanged)
  im2double(I)  = 0.7843       (200/255, class double, range [0,1])

  Check: 200 / 255 = 0.78431... → 0.7843.
  Rule: im2double rescales; double() does not.

  Reverse: J = im2double(uint8(200)) = 0.7843 (double).
           im2uint8(J) = 200  (uint8).
           uint8(J)    = 1    (uint8 of 0.7843 → rounds to 1; classic
                               bug from forgetting the "im2" prefix).

EXAMPLE B — element-wise vs matrix multiplication
--------------------------------------------------------------------------------
A = [1 2; 3 4],  B = [5 6; 7 8].

  A .* B  =  [1·5   2·6 ]  =  [5   12]
             [3·7   4·8 ]     [21  32]     (element-wise)

  A * B   =  [1·5+2·7   1·6+2·8]  =  [19  22]
             [3·5+4·7   3·6+4·8]     [43  50]     (matrix product)

  For image pixel manipulation you almost always want .*. Matrix *
  appears in rotations and linear systems only.

EXAMPLE C — preallocation speedup (Q6.6)
--------------------------------------------------------------------------------
Script measures two implementations of x(i) = i^2 for i = 1:10000.

  Unallocated:  elapsed = 0.002904 s
  Preallocated: elapsed = 0.000373 s

  Speedup = 0.002904 / 0.000373 ≈ 7.79×
  Rule: preallocate when you know the final size. MATLAB allocates a new
  block of memory every time you append; preallocated zeros() avoids
  that copy.

EXAMPLE D — vectorization speedup (Q6.8)
--------------------------------------------------------------------------------
Same 10000-element loop.

  Unallocated: 0.002937 s
  Preallocated: 0.000263 s
  Vectorized:   0.000185 s   (i = 1:10000; x = i.^2;)

  Speedup vs unallocated:  0.002937 / 0.000185 ≈ 15.9×
  Speedup vs preallocated: 0.000263 / 0.000185 ≈ 1.42×

  Rule: vectorization usually beats both loop forms. The numbers are
  machine-dependent; on the exam, quote the ratio from the exact
  measurement.

EXAMPLE E — display scaling  (Q7.7 pattern)
--------------------------------------------------------------------------------
Image I has range [0, 99] (unusual, but possible if it is 7-bit).

  imshow(I)                 → displays [0,255] range; image looks dark.
  imshow(I, [])             → auto-scales to actual min/max (0,99),
                              showing full contrast.
  imshow(I, [0 99])         → explicit: 0 = black, 99 = white.

  This is the same as the syllabus Q7.7 answer: use imshow(I, [0 99]) to
  map 99 to white and 0 to black.

EXAMPLE F — trace without trace (Q5.18)
--------------------------------------------------------------------------------
If Y is an n × n matrix, then

  trace(Y)     =  sum(diag(Y))

  Example: Y = [1 2 3; 4 5 6; 7 8 9]
           diag(Y) = [1 5 9]
           sum(diag(Y)) = 15
           trace(Y)     = 15

  Reason: trace sums the diagonal entries. diag extracts the diagonal;
  sum then adds them. Equivalent.
