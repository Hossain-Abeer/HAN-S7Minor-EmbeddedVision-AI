1. ESSENCE
--------------------------------------------------------------------------------
L3 is the tool lesson, not a vision lesson. It fixes the three facts that
every later MATLAB exercise silently assumes: (a) a pixel is a matrix
element whose *class* determines its legal range and therefore its arithmetic
behaviour; (b) the difference between elementwise (.*) and matrix (*)
operations; (c) the IPT's own vocabulary (imread / imshow / imtool / imadd …)
which wraps the safe conversions you would otherwise do by hand. Everything
after L3 is "use these functions in this order"; L3 is "know what the
functions assume".

2.3  SIMULINK — THE BLOCK-DIAGRAM ALTERNATIVE
--------------------------------------------------------------------------------
[L3 — "SIMULINK • Building blocks versus code"]
  Simulink is the graphical counterpart to MATLAB scripting: you wire blocks
  instead of writing statements. The slide gives an equivalent pair:

  Script version:
      f = imread('belgie (247).jpg');
      g = imrotate(f, pi/6 * 180/pi);   % from radians to degrees
      imshow(g)

  Simulink version:
      model = 'rotate_image_model';
      open_system(model);
      cs = getActiveConfigSet(model);
      set_param('rotate_image_model/Rotate','Angle','pi');
      SimOut = sim(model,cs);

  Translation: the block model still needs a set_param call to change the
  rotation angle, so Simulink does not remove the need to know the
  parameters — it removes the need to write the loop. The rest of the
  course uses script MATLAB, not Simulink; the slide exists so you know
  the alternative exists.

2.5  DATA CLASSES — THE CENTRAL FACT OF L3
--------------------------------------------------------------------------------
[L3 — "MATLAB – DATA CLASSES"]
  Top-level matrix/array family (screenshot):
      Matrix or Array (full or sparse)
        logical   char   numeric   table   cell   struct
                           |
                        double / single / int8 / uint8 / …

  The distinction that matters: numeric is one branch of many. An image is
  a numeric array; a mask is a logical array; a colormap is a double array;
  a label image from bwlabel is a double array (despite holding integers).

[L3 — "MATLAB – DATA CLASSES" (table)]
  Verbatim, with the range column kept exact:

    Name     Description                                            Bytes
    -------  -----------------------------------------------------  -----
    Double   Double-precision floating point, approx -10^308..10^308   8
    Uint8    Unsigned 8-bit integers, [0, 255]                        1
    Uint16   Unsigned 16-bit integers, [0, 65535]                     2
    Uint32   Unsigned 32-bit integers, [0, 4294967295]                4
    Int8     Signed 8-bit integers, [-128, 127]                       1
    Int16    Signed 16-bit integers, [-32768, 32767]                  2
    Int32    Signed 32-bit integers, [-214783648, 2147483647]         4
    Single   Single-precision floating point, approx -10^38..10^38    4

  The three classes the course actually uses:
      uint8    — standard 8-bit grayscale and RGB storage
      double   — all arithmetic before display; range [0,1] for images
      logical  — masks, BW images, roipoly output

  Why the class matters (the L3 warning):
    uint8 arithmetic SATURATES at 255 and FLOORS at 0. It does not wrap,
    and it does not go negative.
        uint8(200) + uint8(100)   →  255   (not 300, not 44)
        uint8(10)  - uint8(50)    →    0   (not -40)
    double arithmetic does neither. This is the entire reason IPT provides
    imadd/imsubtract/immultiply/imdivide — they choose the safe behaviour
    for you (L4 covers the details).

  Bounded-range consequence for L1 arithmetic:
    file size and bit depth are always expressed against these ranges.
      uint8  → 256 levels,  8 bits  → 1 byte/pixel
      uint16 → 65536 levels, 16 bits → 2 bytes/pixel
      double → not a storage format; stored as 8 bytes/pixel in memory
               regardless of the visual bit depth.

2.6  MATRIX OPERATIONS AND STANDARD ARRAYS
--------------------------------------------------------------------------------
[L3 — "MATLAB – SPECIALIZED MATRIX OPERATIONS"]
  Verbatim table:

    Name                     MATLAB operator or function
    -----------------------  ----------------------------
    Matrix transpose         apostrophe (') operator
    Inversion                inv
    Matrix determinant       det
    Flip up and down         flipud
    Flip left and right      fliplr
    Matrix rotation          rot90
    Matrix reshape           reshape
    Sum of diagonal elements trace

  Note the two distinct transpose forms:
      A'    conjugate transpose (Hermitian) — flips sign of imaginary part
      A.'   plain transpose
  For real-valued images they are identical; for complex FFT results (L8)
  they are not. L8's fft2 output is complex, so this distinction matters.

[L3 — "MATLAB – STANDARD ARRAYS"]
  Verbatim table:

    zeros(m,n)    m-by-n matrix of zeros
    ones(m,n)     m-by-n matrix of ones
    true(m,n)     m-by-n matrix of logical ones
    false(m,n)    m-by-n matrix of logical zeros
    eye(n)        n-by-n identity
    magic(m)      m-by-m magic square
    rand(m,n)     uniform pseudorandom in [0,1]
    randn(m,n)    normal pseudorandom, mean 0, variance 1

  Two facts that matter downstream:
    true/false produce LOGICAL class — this is how you build masks without
    going through roipoly (L9 region-of-interest processing).
    rand vs randn: rand is uniform (used for uniform noise in L9), randn is
    Gaussian (used for Gaussian noise in L9). Confusing them changes the
    noise model, not just the numbers.

2.7  OPERATORS — ARITHMETIC, RELATIONAL, LOGICAL
--------------------------------------------------------------------------------
[L3 — "MATLAB – ARITHMETIC OPERATORS"]
  Verbatim table, split by elementwise vs matrix:

    Operator  Meaning                        Function
    --------  -----------------------------  ---------
    +   -     array and matrix add/subtract  plus, minus
    .*        element-by-element multiply    times
    *         matrix multiplication          mtimes
    ./        array right division           rdivide
    .\        array left division            ldivide
    /         matrix right division          mrdivide
    \         matrix left division           mldivide
    .^        array power                    power
    ^         matrix power                   mpower
    .'        vector and matrix transpose    transpose
    +         unary plus                     uplus
    -         unary minus                    uminus

  The single most important row for this course:  .* versus *
    .*  multiplies corresponding pixels  → the image-processing operation
    *   multiplies matrices              → a geometric transformation
  L4 opens with exactly this distinction (§8.1 of the syllabus is titled
  "Elementwise versus matrix operations").

[L3 — "MATLAB – RELATIONAL AND LOGICAL OPERATORS AND FUNCTIONS"]
  Relational (return logical):
    <    <=    >    >=    ==    ~=
  Logical (combine logicals):
    &  AND        |  OR         ~  NOT
  Functions:
    xor    exclusive-or between two operands
    all    returns 1 if ALL vector elements are nonzero, else 0
           (operates columnwise on matrices)
    any    returns 1 if ANY vector element is nonzero, else 0
           (operates columnwise on matrices)

  Consequence for masks (used in L9, L10):
    A & B     pointwise AND of two masks
    A | B     pointwise OR
    ~A        complement
    A == B    elementwise comparison — the basis of the Q8/Q9/Q11 "are these
              two images equal?" verification scripts.

[L3 — "MATLAB – SELECTED BUILT-IN VARIABLES AND CONSTANTS"]
  Verbatim table:

    ans     most recent answer
    eps     floating-point relative accuracy
    i / j   imaginary unit (sqrt(-1))
    NaN     Not-a-Number (e.g. 0/0)
    Inf     Infinity (e.g. division by 0)
    pi      nearest floating-point value of pi
    clock   matrix with date and time
    date    current date as a string

  Two of these are examinable as *behaviour*, not as values:
    NaN propagates: any arithmetic with NaN yields NaN. This is why
    division-by-zero in a filter (L9 inverse filtering) must be guarded.
    Inf propagates and dominates: 1/0 = Inf, and 9/Inf = 0. This is exactly
    the harmonic-mean failure on pepper noise (Q15-4): 1/0 = Inf in the
    denominator drives the filtered value to 0 (black).

2.8  SCRIPTS AND FUNCTIONS
--------------------------------------------------------------------------------
[L3 — "MATLAB – SCRIPTS AND FUNCTIONS"]
  An M-file is either a script or a function.

  SCRIPT
    • A sequence of commands to be interpreted and executed.
    • May contain variable declarations, calls to user-created functions,
      decision statements and repetition loops.
    • Created in the Editor, saved with a meaningful name and .m extension.
    • Invoked by typing its name at the prompt.

  FUNCTION (structure, verbatim from slide):
    1. The function definition line:
           function [outputs] = function_name(inputs)
    2. The H1 line — a single comment line immediately after the definition
       line. It is the first text shown by "help function_name".
    3. The help text — a block of comments after the H1 line, displayed by
       "help function_name".
    4. The function body — all the code that computes and assigns outputs.

  Operational fact: the H1 line is what "help raise_to_power" prints first.
  If you write a function without an H1 line, the help command returns an
  empty first line.

[L3 — "MATLAB – SCRIPTS AND FUNCTIONS • Anonymous function"]
  Verbatim example:
      sqr = @(x) x.^2;
      a = sqr(5)        % a = 25

  Anonymous functions are used in L9/L15 as filter kernels passed to
  nlfilter:
      fun = @(x) trimmean(x(:),25);
      I_filt = nlfilter(In2,[5 5],fun);
  The @(x) … form lets you pass a one-line kernel without creating a .m file.

[L3 — "MATLAB – CONTROL STATEMENTS • For loop"]
  Verbatim annotation:
    • Repeats for a specific number of times
    • Always executes computation loop at least once
    • Can escape (break) out of computational loop
  Code form:
      for j = 1:10
          % computations
      end

  [note] The slide's "always executes at least once" wording is imprecise
  for a for-loop with an empty range (1:0 executes zero times). The
  guarantee belongs to do-while, which MATLAB lacks. The slide's intent is
  "runs the stated number of times", not "runs unconditionally".

[L3 — "MATLAB – CONTROL STATEMENTS • While loop"]
  Verbatim annotation:
    • Will do computational loop only if while condition is met
    • Be careful to initialize while variable
    • Can loop forever if while variable is not updated within loop
  Code form:
      k = 0;
      while k < 10
          % computations
          k = k + 1;      % change k
      end

  The two warnings on the slide (initialise before, update inside) are the
  two ways a while loop fails. Both appear in practice as an infinite loop
  and a frozen Command Window.

[L3 — "MATLAB – CONTROL STATEMENTS • If statements / If-elseif"]
  Verbatim annotation:
    • Can include multiple statements
    • Statements can also include other if statements (nested if)
    • Be careful not to overlap (crossover) if statements
    • If-elseif: can have several elseif conditions
    • Else is optional and executes if all other tests fail

  Used in L13/L14 to build a heuristic classifier:
      if (TR(k) > 0.9)
          name{1,k} = 'circle';
      elseif (TR(k) > 0.8)
          name{1,k} = 'square';
      else
          name{1,k} = 'other';
      end

[L3 — "MATLAB – TIMING • TIC • TOC • Vectorization"]
  Verbatim list: TIC, TOC, Vectorization.
    tic starts a stopwatch; toc reads it.
    Vectorization = replacing a loop with a matrix operation.

[L3 — "MATLAB – TIMING • Profile on • Profile viewer • Multithreading"]
  Verbatim list: profile on, profile viewer, multithreading.
    profile on / profile viewer produce a per-line timing report — used when
    tic/toc identifies a slow section but not the slow line inside it.

2.10  IPT ESSENTIAL FUNCTIONS
--------------------------------------------------------------------------------
[L3 — "IPT- ESSENTIAL FUNCTIONS • Data classes and data conversions"]
  Common image classes (verbatim): uint8, double, logical.
  Conversion table (verbatim):

    Function    Converts image to class   |  Function   Converts … into …
    ----------  -----------------------   |  ---------  -----------------------
    im2single   single                    |  ind2gray  indexed → grayscale
    im2double   double                    |  gray2ind   grayscale → indexed
    im2uint8    uint8                     |  rgb2gray  RGB → grayscale
    im2uint16   uint16                    |  rgb2ind   RGB → indexed
    im2int16    int16                     |  ind2rgb   indexed → RGB

  Two conversion traps the course relies on:
    1. im2double SCALES. im2double(uint8(255)) = 1.0, not 255.
       double(uint8(255)) = 255 (no scaling). The difference changes every
       subsequent multiplication.
    2. ind2gray / ind2rgb APPLY THE COLORMAP. Converting an indexed image
       to grayscale without going through the colormap gives the wrong
       result — the pixel values are indices, not intensities.

[L3 — "IPT – ESSENTIAL FUNCTIONS • Displaying the contents of an image"]
  Verbatim distinctions:
    image    — displays an image using the CURRENT colormap.
    imagesc  — scales image data to the full range of the current colormap,
               then displays.
    imshow   — displays an image with a number of optimizations and optional
               parameters for property settings associated with image display.
    imtool   — displays an image and contains a number of associated tools
               for exploring the image contents.

  The operational difference that matters:
    imshow(I)       assumes the data class defines the display range
                    (uint8 → 0..255; double → 0..1).
    imshow(I,[])    auto-scales min→black, max→white. This is the "[] second
                    argument" used throughout L8 (FFT magnitude), L9
                    (Laplacian), L15 (scaled difference images) and L17.
    Without [], a double image with values outside [0,1] displays as pure
    black or pure white with no detail.

[L3 — "IPT – ESSENTIAL FUNCTION • Exploring the contents of an image"]
  imtool — verbatim: "Provides all the image display capabilities of imshow
  as well as access to other tools for navigating and exploring images, such
  as the Pixel Region tool, Image Information tool, and Adjust Contrast
  tool."

  Two companion functions appear in Syllabus §7 (not on the L3 slide but in
  the same toolbox family and used by Q7-7/Q7-8):
      impixelinfo   — status-bar readout of pixel value under the cursor
      impixel       — returns r, c, p for clicked points

[L3 — "IPT – ESSENTIAL FUNCTIONS" (arithmetic table)]
  Verbatim:

    Function      Description
    ------------  ------------------------------------------------------
    imadd         adds two images or adds a constant to an image
    imsubtract    subtracts two images or a constant from an image
    immultiply    multiplies two images (element-by-element) or a constant
                  times an image
    imdivide      divides two images (element-by-element) or an image by a
                  constant
    imabsdiff     absolute difference between two images
    imcomplement  complements an image
    imlincomb     linear combination of two or more images

  The invariant: all seven handle class truncation, saturation, and

4. SUMMARY (exam-ready, 10 bullets)
--------------------------------------------------------------------------------
1. MATLAB = MATrix LABoratory. Chosen for prototype speed, not run-time
   speed. IPT is the toolbox the course uses most.
2. Working environment: Current directory, script files, Workspace,
   Command Window. A script can only imread from the current directory or
   the search path.
3. Data classes that matter: uint8 [0,255] 1 B; uint16 [0,65535] 2 B;
   double ([-10^308,10^308], 8 B); logical {0,1}, 1 B.
   uint8 arithmetic SATURATES: 200+100 = 255, 10−50 = 0.
4. im2double SCALES to [0,1]; double() does not. This changes every
   subsequent multiplication.
5. Elementwise (.*  ./  .^) versus matrix (*  /  ^). The course is
   elementwise unless stated otherwise.
6. Standard arrays: zeros, ones, true, false, eye, magic, rand (uniform),
   randn (Gaussian). rand vs randn = different noise model, not different
   numbers.
7. Built-in constants: ans, eps, i/j, NaN, Inf, pi, clock, date.
   NaN propagates; Inf dominates (1/0 = Inf; 9/Inf = 0).
8. M-files: scripts (sequence of commands) vs functions
   (function [out] = name(in), H1 line, help text, body).
   Anonymous functions: sqr = @(x) x.^2.

6. HAND-CALC WORKED EXAMPLES

EXAMPLE A — uint8 saturation vs double arithmetic
--------------------------------------------------------------------------------
Given X = uint8(200), Y = uint8(100), Z = uint8(50):

  X + Y in uint8          = 255      (saturated; true sum 300)
  double(X) + double(Y)   = 300      (class double, no saturation)
  uint8(300)              = 255      (cast back saturates again)
  Y − Z in uint8          = 50       (100 − 50, no saturation)
  Z − Y in uint8          = 0        (true result −50, floored to 0)
  double(Z) − double(Y)   = −50      (preserved in double)

  Exam relevance: the same arithmetic on a uint8 image and on a double
  image produces different pictures. The IPT functions imadd / imsubtract
  exist precisely so you do not have to remember this.

EXAMPLE B — im2double vs double
--------------------------------------------------------------------------------
Given I = uint8 with a pixel value 51.

  im2double(I)  = 51 / 255  = 0.2        (range compressed to [0,1])
  double(I)     = 51                     (range unchanged)
  im2uint8(0.2) = 51                     (round-trip back)

  Now multiply by 2:
  im2double → 0.4 → im2uint8 → 102
  double    → 102 → uint8    → 102
  Same numeric outcome HERE, but:
  double(255) × 2  = 510, and uint8(510) = 255  (saturated, information lost)
  im2double(255) × 2 = 2.0, and im2uint8(2.0) = 255 (also saturated, but
                     the intermediate is honest — you can still divide back)
  L4's dynamic-scaling example (multiply moon by 1.2) depends on this.

EXAMPLE C — elementwise vs matrix multiplication
--------------------------------------------------------------------------------
Given two 2×2 images:
    A = [1 2; 3 4]        B = [5 6; 7 8]

  Elementwise  A .* B  =  [1·5  2·6 ; 3·7  4·8]
                       =  [ 5   12 ;  21   32 ]

  Matrix       A * B   =  [1·5+2·7   1·6+2·8 ; 3·5+4·7   3·6+4·8]
                       =  [ 5+14    6+16  ; 15+28    18+32 ]
                       =  [ 19      22   ; 43       50   ]

  Image processing uses .* almost exclusively (pixel-by-pixel). Matrix
  multiplication is reserved for geometric transformations (L5 affine
  matrices) and linear algebra (eigen-analysis of GLCM in L13).

EXAMPLE D — uint8 bitwise operations  (sample-exam Q4 pattern)
--------------------------------------------------------------------------------
Given X = uint8([200 100 100; 0 10 50; 50 250 120]) and
      Y = uint8([100 220 230; 45 95 120; 205 100 0])

  Bitwise AND (bitand(X,Y)) — keep bits set in BOTH:
      200 = 1100 1000   100 = 0110 0100   →  AND = 0100 0000 =  64
      100 = 0110 0100   220 = 1101 1100   →  AND = 0100 0100 =  68
      100 = 0110 0100   230 = 1110 0110   →  AND = 0110 0100 = 100
        0 = 0000 0000    45 = 0010 1101   →  AND = 0000 0000 =   0
       10 = 0000 1010    95 = 0101 1111   →  AND = 0000 1010 =  10
       50 = 0011 0010   120 = 0111 1000   →  AND = 0011 0000 =  48
       50 = 0011 0010   205 = 1100 1101   →  AND = 0000 0000 =   0
      250 = 1111 1010   100 = 0110 0100   →  AND = 0110 0000 =  96
      120 = 0111 1000     0 = 0000 0000   →  AND = 0000 0000 =   0

  Bitwise OR (bitor) — keep bits set in EITHER:
      200 = 1100 1000   100 = 0110 0100   →  OR  = 1110 1100 = 236
      ... and so on.

  Bitwise XOR (bitxor) — keep bits set in exactly one:
      200 = 1100 1000   100 = 0110 0100   →  XOR = 1010 1100 = 172
      ... and so on.

  Practical meaning (sample-exam answer):
    AND  → dark regions dominate (only common bright bits survive)
    OR   → brighter than both inputs
    XOR  → highlights where the two images differ

  Note: these operations require uint8 (or another integer class). Applied
  to double, they are undefined. That is the L3 → Q4 dependency.

EXAMPLE E — vectorization timing (order-of-magnitude arithmetic)
--------------------------------------------------------------------------------
Loop, no preallocation (MAX_CNT = 10000):    0.002904 s
Loop, preallocated:                          0.000373 s
Vectorized (i .^ 2):                         0.000185 s

  Speed-ups:
    preallocation vs none:      0.002904 / 0.000373  ≈ 7.8×
    vectorization vs none:      0.002904 / 0.000185  ≈ 15.7×
    vectorization vs prealloc:  0.000373 / 0.000185  ≈ 2.0×

  These are the numbers from the Q6 answer PDF. The exact ratios are
  hardware-dependent; the ORDER (vectorized < preallocated < naive loop) is
  not.

EXAMPLE F — image equality verification
--------------------------------------------------------------------------------
The syllabus repeats this idiom four times (Q8-7, Q9-7, Q11-2, Q16-15).
The General Formula is:

    if A == B
        disp('A is equal to B');
    else
        disp('A and B are not the same');
    end

  Why the short form works: A == B returns a logical array the same size
  as A and B. In an if-condition MATLAB treats the array as true only if
  ALL elements are true. That is why the one-line test succeeds without
  any all() call — although all(A(:) == B(:)) is the explicit equivalent.
